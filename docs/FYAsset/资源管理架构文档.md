## 设计目标

用自研 AssetBundle 资源管理系统逐步替换 Addressables 的资源加载机制。当前 AA 路径（基于 Addressables）和 AB 路径（自研）已经具备独立 runtime、hotfix、build 入口；旧 public 名称保留为兼容门面，便于现有调用点迁移。

### 路径规范

FYAsset 将路径分为三类处理：

- 远端 URL：使用 `FYAssetPathUtility.JoinUrl(...)`，不依赖当前后端 `HotfixUrl` 是否带尾斜杠。
- 本地文件系统路径：使用 `FYAssetPathUtility.JoinFilePath(...)` / `ResolveFilePath(...)`，配置根、CLI 输出根、发布根、临时构建目录和 `StreamingAssets` 导出都按本地路径语义处理。
- Unity AssetDatabase 路径：保持 `Assets/...` 与 `/` 分隔符，使用 `NormalizeAssetPath(...)` / `JoinAssetPath(...)`；不得当成本地绝对路径拼接。

Android `StreamingAssets` 这类 `jar:` URI-like 路径不会被当作普通本地盘符规范化，拼接时保持 `/` 分隔符。

## AA（基于 Addressables）vs AB（自研）对比

| 维度       | AA (Addressables)                      | AB (自研)                                               |
| -------- | -------------------------------------- | ----------------------------------------------------- |
| **索引源**  | AAManifest (+ Addressables catalog)    | ABManifest（JSON + Binary）                            |
| **加载后端** | AddressablesBackend → Addressables API | ABPackageBackend → AssetBundle API                    |
| **依赖解析** | Addressables 内部自动处理                    | ABBundleLoader 递归解析 Bundle 级依赖                        |
| **引用计数** | 单层（AsyncOperationHandle）               | 双层（Bundle 级 + Asset 级）+ Handle 层对外暴露                  |
| **资源标识** | Address 唯一，只有 Labels 标签                | Address 可重复，EntryId(GUID) 唯一，引入 PrimaryType，保留 Labels |
| **错误处理** | 异常 + null                              | RuntimeMessage 结构化错误码，(T, error) 元组，不抛异常               |
| **句柄模型** | 直接返回 T / AssetHandle\<T>           | AssetHandle\<T> struct + HandleRegistry               |

## 核心数据结构

以下数据结构是 FYAsset 模块的骨架，构建期和运行期围绕它们展开。

### ManifestAssetEntry（资产索引项）

构建期生成，描述单个资产的元数据。运行时通过 `ToRuntimeEntry()` 转换为 `RuntimeAssetEntry`。

```csharp
public class ManifestAssetEntry
{
    // 运行时必须字段
    public string EntryId;       // 唯一资源ID（GUID）
    public string Address;       // 可寻址逻辑名（允许重复，不是唯一身份）
    public string PrimaryType;   // 资源类型名（如 "Texture2D"、"Mesh"）
    public List<string> Labels = new();  // 分类标签

    public int BundleIndex;      // 所属 Bundle 索引

    // 编辑器字段
    public string SourcePath;    // 资源文件路径（构建时使用）
    public string Group;         // 资源分组（构建时使用）

    public RuntimeAssetEntry ToRuntimeEntry() { }
}
```

### ManifestBundleEntry（Bundle 索引项）

构建期生成，描述一个 AssetBundle 的元数据。

```csharp
public class ManifestBundleEntry
{
    public string BundleName;           // Bundle 文件名
    public string FileHash;             // 文件哈希值（MD5）
    public long FileSize;               // 文件大小（字节）
    public uint FileCRC;                // CRC32 值
    public bool Encrypted;              // 是否加密

    public string BundleType = "";       // 内容类型（如 "Texture2D" / "Mixed"，构建管线 >80% 阈值自动推断）
    public List<string> Tags = new();   // 分类标签，用于 DLC 等分包策略
    public int[] DependBundleIndices = new int[0];  // 依赖的 Bundle 索引

    [NonSerialized]
    public List<ManifestAssetEntry> IncludeAssets = new();
    [NonSerialized]
    public List<int> ReferencedByBundleIndices = new();
}
```

### ABManifest（AB 资源清单）

构建期导出，运行期读取。完整描述一次构建产出的所有资源与 Bundle 的映射关系。

```csharp
public class ABManifest
{
    public string PackageName;
    public VersionNumber PackageVersion;
    public string BuildTimestamp;              // ISO 8601 格式
    public List<ManifestAssetEntry> AssetEntries = new();
    public List<ManifestBundleEntry> BundleEntries = new();    // 完整运行时 Bundle 表
    public List<ManifestBundleEntry> DeliveryBundles = new();  // Hotfix 实际交付 Bundle；Full 为空

    // 运行时索引（不序列化，由 Initialize() 构建）
    [NonSerialized] private Dictionary<string, List<int>> _addressIndex;
    [NonSerialized] private Dictionary<string, int> _entryIdIndex;
    [NonSerialized] private Dictionary<string, List<int>> _typeIndex;
    [NonSerialized] private Dictionary<string, List<int>> _labelIndex;
    [NonSerialized] private Dictionary<string, int> _bundleNameIndex;
    [NonSerialized] private bool _initialized;
}
```

### RuntimeAssetEntry（运行时资产条目）

从 Manifest 转换而来，供运行时查询使用。

```csharp
public class RuntimeAssetEntry
{
    public string EntryId;
    public string Address;
    public string PrimaryType;
    public List<string> Labels = new();
    public string SourcePath;
    public string Group;
    public bool AutoAddress;

    private HashSet<string> _normalizedLabelsCache;  // 缓存归一化 Labels 集合
}
```

### AssetHandle\<T>（资产句柄）

主要加载接口的返回类型。值类型（struct），零 GC 分配。

```csharp
public struct AssetHandle<T> where T : UnityEngine.Object
{
    internal int HandleId;          // HandleRegistry 中的槽位索引
    internal int Generation;        // 版本号，防止悬空复用
    private T _cachedAsset;         // 缓存引用，热路径直接返回
    private RuntimeMessage _inlineError;  // 失败句柄的内联错误（HandleId = -1 时使用）

    public T Asset { get; }
    public bool IsValid { get; }
    public RuntimeMessage Error { get; }

    public AssetHandle<T> Retain() { }   // 增加引用计数
    public void Release() { }            // 减少引用计数
}
```

### HandleRegistry（句柄注册表）

内部静态类，管理所有 Handle 的生命周期。

```csharp
internal static class HandleRegistry
{
    private struct Slot
    {
        public int Generation;
        public int RefCount;
        public string EntryId;
        public string BundleName;
        public RuntimeMessage Error;
        public Action<string> ReleaseCallback;  // 引用归零时回调
    }

    private static Slot[] _slots = new Slot[64];
    private static int _count = 0;
    private static readonly Stack<int> _freeList = new();
}
```

### ResolveResult（资源解析结果）

```csharp
public class ResolveResult
{
    public enum ResolveStatus
    {
        Hit,                 // 恰好一条匹配
        NotFound,            // 未找到
        Conflict,            // 多条匹配，需 Labels 消歧
        TypeMismatch,        // 类型不兼容
        IndexNotSupported,   // 当前索引不支持此查询
    }

    public ResolveStatus Status { get; }
    public RuntimeAssetEntry Entry { get; }   // Status == Hit 时非 null
    public RuntimeMessage Error { get; }      // Status != Hit 时非 null
    public bool IsSuccess => Status == ResolveStatus.Hit && Entry != null;
}
```

## Collector 采集与资产元数据

资产收集采用 **Collector 采集 + AssetEntry 元数据** 模型。Collector 只负责编辑器时期的路径发现、过滤、分组路由和 Role/Payload 默认分析；运行时 Address、资产 Labels、Role、Payload 的权威值保存在按 GUID 索引的 `AssetEntry` 中。

- `IFilterRule` — 决定哪些资产被收集
- `IGroupRule` — 决定资产归属哪个 Group
- `AssetEntry` — 保存资产级 Address、Labels、Role、PayloadKind
- `BundlePackingMode` — Group 级打包模式：`PackTogether` / `PackSeparately` / `PackTogetherByLabel`

`CollectionScanner` 负责扫描流程：Collector 所有权映射（deepest-path 优先）→ FilterRule → AssetClassifier → GroupRule → AssetEntry 解析 → BundleNameBuilder 命名。Bundle 命名采用模式段避免 Address/GUID key 与 Labels key 混淆。

> 详细设计见 [Collector 采集与资产元数据](./collector-规则系统.md)

## 依赖分析与共享抽取

构建 Bundle 前，需要分析资产间的依赖关系，决定哪些依赖资产应该提取为共享 Bundle。

- `DependencyAnalyzer` — BFS 扫描资产依赖图，识别被多个 Bundle 引用的共享资产
- `BundleDependencyGraph` — 记录 Bundle 间的依赖边
- `SharePolicyConfig` — 配置共享策略：最小引用数阈值、强制共享/禁止共享规则
- `TaskAnalyzeDependencies` — 作为 Build Pipeline 的一个 Task 执行

分析完成后，共享资产被归入 `shared` Group，与主资产分开打包。

> 详细设计见依赖分析文档（待编写）

## Build Pipeline 构建管线

构建管线采用 **Task + 线性执行列表** 模型：

- `IBuildTask` — Task 接口，声明 `TaskName`、`DependsOn`、`ReadKeys`、`WriteKeys` 和 `Execute(BuildContext)` 方法
- `BuildContext` — 字典式数据容器，Task 间通过它传递数据
- `BuildPipelineRunner` — 按 `BuildPipelineConfig.Tasks` 顺序确定性执行，支持 Validate、stop-after、whitelist 和任务状态回调
- `BuildPipelineConfig` — ScriptableObject 配置，定义 Task 列表和 Bundle 文件名格式
- `BuildTaskResolver` — 通过程序集扫描自动发现 Task 类型，建立 TaskName → Type 映射
- `BackendMode` — 枚举（`AA` / `ABManifest`），显示名为 AA / AB；正式构建后端由 AA/AB concrete build manager 创建 `BuildPackageRequest` 时决定

> 详细设计见 [Build Pipeline 构建管线](./build-pipeline-构建管线.md)

## 热更管线

热更流程由 `AAHotfixManager` / `ABHotfixManager` concrete 入口执行，共用 `HotfixFlowBase`，旧 `HotfixManager` 是兼容门面。11 步流程覆盖：加载 BuildIndex → 初始化后端 → 下载 PackageIndex → 版本比对 → 下载 Bundle → 应用更新 → 完成。AB 路径用 ABManifest 驱动版本和资源定位；AA 路径用 AAManifest 驱动版本/查询索引，并继续依赖 Addressables catalog 做资源定位。

`PackageCleaner` 负责目录清理（大版本清空 + 旧包体轮转）。`NetworkDownloader` 提供网络下载原语，Bundle 下载阶段由 `HotfixFlowBase` 统一做 `.tmp` 写入、CRC 校验、失败重试和同 Hash 复用优化。

> 详细设计见 [热更新系统](./hotfix-热更新系统.md)

## 版本号系统

全项目统一使用 `VersionNumber` 类型（SemVer 2.0：`Major.Minor.Patch-Channel+Build`）。`VersionDataBase` ScriptableObject 在构建期管理版本自增（Major/Minor/Patch 三种模式）。版本比较优先级为 Major → Minor → Patch → ChannelRank，Build 不参与。

> 详细设计见 [版本号系统](./versioning-版本号系统.md)

## AB 运行时加载

AB 运行时加载系统分为三层——**Bundle 层**（ABBundleLoader，AssetBundle 文件加载/卸载）、**Asset 层**（ABPackageBackend，资源提取与缓存）、**Handle 层**（HandleRegistry，外部句柄引用计数）。通过双层引用计数实现精确卸载粒度。

核心组件：`ABManifestLoader` 异步加载清单、`ABAssetIndex` 运行时索引、`AssetResolver` 地址解析、`ABPackageManager` 上层入口。Resolve-And-Handle API 返回 `AssetHandle<T>` 值类型句柄；兼容 `AssetPackageManager` 仍可直接返回资源对象。

> 详细设计见 [AB 运行时加载](./ab-runtime-运行时加载.md)

## 错误处理

采用两层统一架构：构建时 `BuildMessage` 和运行时 `RuntimeMessage`，共享 `Severity × Code × Message` + 工厂方法的设计。所有公开 API 不抛异常，通过返回值传递错误。

> 完整说明见 [错误处理](./错误处理.md)
