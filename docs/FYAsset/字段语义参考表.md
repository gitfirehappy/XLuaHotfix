# 字段语义参考表

> **关联代码** | `Assets/FYAsset/Scripts/Shared/` · `Assets/FYAsset/Scripts/AA/` · `Assets/FYAsset/Scripts/AB/`

本文只记录容易混淆、会影响跨模块行为的语义。完整字段和序列化顺序以源码为准。

---

## 高危混淆项

| 对比 | 结论 |
|------|------|
| Labels / Tags | Labels 属于资产，用于运行时查询；Tags 属于 Bundle，用于下载与分包策略。两者不互通。 |
| Address / AssetPath | Address 是运行时逻辑查询键，允许重复；AssetPath 是编辑器路径，只用于构建和诊断。 |
| EntryId / AssetGUID | 值都来自 Unity GUID；EntryId 是运行时命名，AssetGUID 是构建期命名。 |
| PrimaryType / BundleType | PrimaryType 描述单个资产；BundleType 是 Bundle 内容的主导类型或 `Mixed`。 |
| BundleEntries / DeliveryBundles | BundleEntries 是完整运行时集合；DeliveryBundles 只表示本次 AB Hotfix 相对 Full baseline 的物理交付。 |
| PackageIndex / BuildIndex | 远端 PackageIndex 指向目标包；本地 PackageIndex 指向最近成功激活包；BuildIndex 描述安装包自带基线。 |
| Version / Build | 发布身份是 `Major.Minor.Patch[-Channel]`；Build 只是独立计数，不参与比较，也不进入包名或仓库 object 名。 |

## 配置归属

当前只有三份活跃配置资产：

| 配置 | 负责内容 |
|------|----------|
| `FYAssetSettings` | 项目名、兼容后端开关、全局失败策略、输出根、版本库、BuildIndex、Push Targets |
| `FYAssetAASettings` | AA HotfixUrl、下载参数、AA Pipeline、manifest 输出与 Lua 索引 |
| `FYAssetABSettings` | AB HotfixUrl、下载参数、AB Pipeline、manifest 输出与 Collector 配置 |

`UseABBackend` 只服务旧兼容入口和命令行路由；独立 AA/AB 编辑器窗口不互斥。

## 资源身份链

| 阶段 | 关键结构 | 身份与查询语义 |
|------|----------|----------------|
| Collector | `AssetEntry` / `AssetExclusion` | GUID 是权威键；Address 可自动生成或手动锁定；排除按 GUID 生效。 |
| 构建中间态 | `CollectedAssetInfo` | 汇总路径、GUID、Address、类型、Labels、Package/Group 和 Bundle 路由结果。 |
| Manifest | `ManifestAssetEntry` | EntryId 唯一；Address + 类型 + Labels 用于查询；BundleIndex 指向完整 Bundle 表。 |
| 运行时 | `RuntimeAssetEntry` | 只保留解析与诊断需要的资产视图。 |
| Handle | `AssetHandle<T>` | 通过 HandleId + Generation 管理所有权，错误由 `RuntimeMessage` 传播。 |

Address 冲突不是天然错误：类型或 Labels 能消歧时允许共存；完全无法区分时才返回 Conflict。

## 包体与版本指针

| 结构 | 关键语义 |
|------|----------|
| `VersionNumber` | 比较顺序为 Major → Minor → Patch → Channel；Build 不参与。 |
| `PackageIndex` | 包含 LatestPackage、LatestVersion 和 BackendMode；远端 PackageIndex 指向目标 Hotfix 包，本地 PackageIndex 记录上次成功完成初始化的本地 Hotfix 包。 |
| `BuildIndexData` | 描述安装包基线、平台和后端；Version.Major 是兼容边界，BuildGUID 只标识 Full baseline 身份。 |
| `AAManifest` | AA Bundle 校验信息与 Addressables 查询索引；catalog 仍负责实际定位。 |
| `ABManifest` | 完整资产/Bundle 映射、依赖与 canonical FileHash；Binary schema 当前为 v4。 |
| `ManifestBundleEntry` | BundleName、FileHash、CRC、大小、依赖、BundleType 和 Tags。 |

AA 与 AB 的 PackageIndex、发布目录和 Repository Channel 必须隔离。

## 枚举边界

| 枚举 | 解决的问题 | 关键值 |
|------|------------|--------|
| `ECollectorType` | 资产如何进入采集 | Main、Static、Depend、Implicit |
| `EPayloadKind` | 资产如何输出 | Serialized、RawFile、Scene |
| `EAssetRole` | 资产在依赖图中的角色 | Main、Static、Depend、ImplicitDependency |
| `EForcePayloadKind` | 是否覆盖自动分类 | Auto 或强制 Serialized/RawFile/Scene |
| `BundlePackingMode` | Group 如何形成 Bundle | PackTogether、PackSeparately、PackTogetherByLabel |

Role 与 PayloadKind 正交：一个资产“为什么被收集”和“以什么格式输出”不能混成同一枚举。

## BuildContext 使用原则

BuildContext 是 Task 间数据总线，不是长期状态：

1. 请求与环境由准备阶段写入。
2. 采集、依赖、构建、manifest、验证、差异和输出按线性阶段传递。
3. 必需输入使用 `Require<T>`，可选输入使用 `Get<T>`。
4. 标准 Key 统一放在 `BuildContextKeys`；不要在 Task 内发明同义字符串。
5. 精确 Key 列表以 `BuildContextKeys.cs` 和 Pipeline 文档为准。

## 命名规则

- 对外字段使用 PascalCase；同语义跨结构保持同名。
- 资产级分类统一叫 Labels，Bundle 级策略统一叫 Tags。
- 文件内容哈希统一叫 FileHash。
- Address 不承诺唯一；EntryId 才承诺唯一。
- 本地文件路径、AssetDatabase 路径和 URL 使用各自的路径工具，不混用拼接规则。
