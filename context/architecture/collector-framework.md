# Collector Framework

Last reviewed: 2026-06-01

## Scope

This document describes the verified build-time collector foundation currently present in `Assets/FYAsset/Scripts/Build/Collector/`.

It is an editor/build-time framework. It is not the runtime loading backend and does not define Lua bridge behavior.

## Editor Workflow

`AssetsCollectionPanel` uses a Scan / Preview / Curate workflow.

- Project Scan builds a read-only preview from project assets and `AssetCollectionSetting.IgnorePatterns`. It does not mutate saved Packages or the current Curate candidate.
- `Confirm To Curate` is the explicit boundary that copies the current scan preview into editable Curate data.
- Returning to Curate from Scan or Preview without confirmation reloads the saved/current `AssetCollectionSetting` and runs `CollectionScanner.Scan` only to populate navigation and details.
- Save persists Curate data, reloads it, rebuilds the scan result used by the sidebar/details view, and preserves existing sidebar expansion state.
- The Curate sidebar defaults to Package-expanded and Group-collapsed; expanding a Group reveals asset rows.

## Configuration Hierarchy

The collection model is a four-level hierarchy plus a GUID-keyed asset metadata registry:

`AssetCollectionSetting -> AssetCollectionPackage -> AssetCollectionGroup -> Collector`

`AssetCollectionSetting.AssetEntries` stores asset-level metadata by Unity asset GUID.

### `AssetCollectionSetting`

- ScriptableObject root.
- Stores all configured packages.
- Stores project-level `AddressStyle` for automatic Address generation.
- Stores `AssetEntries`, keyed by `AssetGUID`.
- Default build settings path is `Assets/FYAsset/CollectorData/CollectorSetting.asset`.

### `AssetCollectionPackage`

- Top-level package boundary.
- Holds `PackageName`.
- Owns a list of `AssetCollectionGroup`.
- Owns per-package `SharePolicyConfig`.

### `AssetCollectionGroup`

- Addressables-like configuration domain.
- Holds `GroupName`, `Enabled`, inherited group `Labels`, and `BundlePackingMode`.
- Owns a list of `Collector`.
- Group Labels are mandatory inherited labels for every asset resolved into the Group.

### `Collector`

- Editor-time asset discovery and analysis entry.
- Stores:
  - `CollectPath`
  - `CollectPathType`
  - `CollectorType`
  - `ForcePayloadKind`
  - `FilterRuleName`
  - `GroupRuleName`

Collector does not store runtime/business Address, Labels, ignore patterns, or bundle packing metadata.

Manual collector configuration supports only `Main`, `Static`, and `Depend` collector types. `Implicit` is system-generated by dependency analysis and must not be selected for user-authored collectors.

### `AssetEntry`

- Asset-level authoritative metadata keyed by Unity GUID.
- Stores:
  - `AssetGUID`
  - `AutoAddress`, `Address`
  - `Labels`
  - `AutoRole`, `Role`
  - `AutoPayload`, `PayloadKind`

Newly discovered assets are initialized from Collector analysis. Existing AssetEntry data is not silently overwritten by rescans; editor Reset Auto actions restore generated Address, Role, or Payload values independently.

## Rule Contracts

The active editor-side rule system has two interfaces:

- `IFilterRule`
- `IGroupRule`

`RuleResolver` resolves rule class names through reflection and caches instances.

Address and bundle packing are not rule interfaces anymore. Address comes from `AssetEntry` or `AssetAddressGenerator`; bundle grouping comes from `AssetCollectionGroup.BundlePackingMode`.

Automatic Address styles are project-level state:

- `ShortName`: filename without extension.
- `LongAssetPathWithoutExtension`: normalized Unity asset path without extension.
- `NameType`: short name plus `#` plus primary type.

The scanner does not rewrite Address values because of short-name conflicts. Address duplication is allowed until the runtime resolver identity (`Address + PrimaryType + Labels`) cannot disambiguate entries.

## Metadata Resolution

`CollectionScanner.Scan(AssetCollectionSetting)` resolves each collected asset in this order:

1. Collector path ownership.
2. `IFilterRule` collectability.
3. Collector `AssetClassifier` analysis for role and payload defaults.
4. `IGroupRule` target Group routing.
5. AssetEntry lookup or creation by GUID.
6. Address resolution:
   - `AutoAddress=true`: generated address.
   - `AutoAddress=false`: manual `Address`.
7. Classification resolution:
   - `AutoRole=true`: Collector-analyzed role.
   - `AutoRole=false`: manual `Role`.
   - `AutoPayload=true`: Collector-analyzed payload.
   - `AutoPayload=false`: manual `PayloadKind`.
8. Label resolution:
   - `FinalLabels = Group.Labels + AssetEntry.Labels`.
   - Group Labels cannot be removed by AssetEntry.
9. Bundle name generation from Group `BundlePackingMode`.

## Bundle Packing

`BundlePackingMode` is configured on Group:

- `PackTogether`
- `PackSeparately`
- `PackTogetherByLabel`

Scene assets force `PackSeparately` behavior. This only affects packing mode; the same bundle naming rules apply.

Bundle logical names are:

- `PackTogether`: `{package}_{group}_all`
- `PackSeparately`: `{package}_{group}_asset_{normalizedAddress}~{shortGuid8}`
- `PackTogetherByLabel`: `{package}_{group}_labels_{labelA}~{labelB}`
- no labels: `{package}_{group}_labels_$unlabeled`

For `PackSeparately`, `normalizedAddress` is a bundle-key-safe projection of the asset Address. The asset Address remains asset metadata and may contain characters that are not valid inside bundle keys.

`BundleKey` is an intermediate build bucket key. It is not a runtime query field, not a business label, and not Collector output.

## Classification Behavior

`AssetClassifier` maps `ECollectorType` into `EAssetRole`:

- `Main -> Main`
- `Static -> Static`
- `Depend -> Depend`

`EForcePayloadKind` controls payload behavior:

- `Serialized` forces serialized payload.
- `RawFile` forces raw-file payload.
- `Scene` forces scene payload.
- `Auto` infers `.unity` as `Scene`, known Unity asset extensions as `Serialized`, and other files as `RawFile`.

Collector therefore retains payload analysis capability, including RawFile recognition.

## Validation

`AssetCollectionSettingValidator` blocks invalid collection settings before scanner execution:

- missing or duplicate package/group names
- invalid reserved characters in package/group/labels
- invalid collector paths
- invalid manual collector type
- invalid filter/group rule names
- duplicate asset entries by GUID
- cross-package collect path overlap
- same-path conflicts

User-authored Package, Group, and Labels reject reserved bundle-name characters including `$`. System identifiers such as `$shared` and `$unlabeled` are generated by framework code.

`#` is allowed in asset Address for the explicit `NameType` style, but it is reserved for Package, Group, Label, and BundleKey values. PackSeparately bundle keys normalize Address text before bundle-name assembly, so `#` is projected out of bundle names.

## Intermediate Build Model

### `CollectedAssetInfo`

- Flattened editor-time representation of one collected asset.
- Contains resolved Address, final Labels, GroupLabels, AssetLabels, BundleName, BundlePackingMode, and `AssetClassification`.
- Used by dependency analysis, builtin collection, bundle build, and manifest generation.

### `AssetClassification`

- Describes asset role and payload kind.
- Used by scanner, dependency analysis, and build tasks.

## What This Document Does Not Claim

This document does not claim that the collector framework has replaced the runtime loading backend. The repository still uses the runtime and release flow described in `resource-build-and-release.md`.
