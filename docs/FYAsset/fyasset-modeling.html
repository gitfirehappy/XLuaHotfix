一套外壳，两条内容链

Shared 只拥有线性 Task 编排、版本、无状态文件摘要与差异、发布事务和热更状态机；AA/AB 各自拥有内容格式与加载器。Shared 不引用 Catalog、AAManifest、ABManifest、Bundle 构建结果或 Collector 等后端字段。

03

三种身份不能互相代替

启动与热更的核心不是“读一个 Manifest”，而是先确定安装包身份与运行模式，再由唯一激活包根的内容描述驱动校验和加载。

BuildIndexData

安装包内置身份。给出 BuildGUID、Version、Platform、BackendMode 与 RuntimeMode，是启动的安装包身份，不指向远端包。

PackageIndex

本地活动包或远端目标指针。LatestPackage 与 LatestVersion 必须成对可信，BackendMode 必须匹配当前 flow。

AA/AB Manifest

包内内容描述。AA 依赖 catalog 完成定位；ABManifest 自带 Asset、Content 与内容依赖下标。

VersionNumberstruct；比较与相等性忽略 Build。JSON 缺版本对象拒绝，显式 0.0.0 合法。
FileDigest / FileDiff名称按 Ordinal 比较；Hash/CRC/Size 任一不同即 Modified。无状态，不读历史。
Labels / BundleKeyLabels 属于资产查询；BundleKey 是构建期内容分桶键，不进入运行时。
Packages / Hotfix / HotfixPublish构建交付包、累计 Hotfix 目录、发布镜像三者职责分离。
04

交付与发布是两个事务边界

构建先写 attempt，Runner 成功后提升正式输出，再由 BuildProjectRunner 提交本地启动数据、累计 Hotfix 目录与版本；发布在服务器隔离目录组装并校验，最后才写 PackageIndex。

01 ATTEMPT主干只写 attempt 中间目录，失败不触碰正式输出。
02 PROMOTERunner 成功后提升正式输出，保留回滚材料。
03 BOOTSTRAPFull / Standalone 写 StreamingAssets 启动数据。
04 ACCUMULATIONFull 重置累计 Hotfix 目录；Hotfix 写入累计结果。
05 VERSION最后应用 VersionRecord 并提交构建缓存。
P1 SERVER FACTS读服务器 PackageIndex 与其指向的 Manifest。
P2 STAGE隔离目录组装，复用服务器已有 Hash 内容。
P3 VERIFY校验清单齐全、文件集合与摘要一致。
P4 APPLY就位不可变新包目录，不覆盖当前指向目录。
P5 INDEX最后写 PackageIndex；旧包清理是独立入口。
失败路径：交付按相反顺序恢复 VersionRecord、累计目录、本地启动数据与包目录；发布按相反顺序恢复 PackageIndex 与包目录。补偿失败会记录并继续处理其余步骤；不保证崩溃原子性。发布不删除旧包，远端部署失败也不能证明远端完全未变化。

自动化不能替代的验收
