# 序列化工具

> **关联代码** \| `Assets/Tools/Scripts/Serialization/`

## 概述

这套工具提供一套工程化的二进制序列化方案：将 C# 数据对象稳定地序列化为字节流，再稳定地反序列化回来。当前主要服务于运行时需要快速读写的结构化数据（如 `ABManifest`）。

定位不是"万能存档系统"——它适合结构稳定、需要紧凑读写、在工程内闭环使用的数据类型。

---

## 架构设计

```
BinaryCodec（总入口：注册类型、路由读写）
  ├─ BinaryHeader（8 字节头：Magic + SchemaVersion + Flags）
  ├─ {TypeName}_BinarySerializer（生成代码：类型级包装）
  └─ BinaryReflectionSerializer（底层：按字段 Order 递归读写）
```

### BinaryHeader

每份序列化数据前的固定 8 字节头：

| 字段 | 大小 | 作用 |
|------|------|------|
| Magic | 4 bytes | 标识数据类型，路由到正确的反序列化处理器 |
| SchemaVersion | 2 bytes | 结构版本，用于兼容性检查 |
| Flags | 2 bytes | 预留 |

头的作用是让任意一段字节流能被"识别身份"——不会把 A 类型的数据错读成 B 类型。

### 代码生成

项目不手写每个类型的序列化器。生成器扫描带 `[BinarySerializable]` 的类型，产出 `{TypeName}_BinarySerializer.cs`，把 Magic / SchemaVersion / WriteWithHeader / ReadWithHeader 包装好。底层复用统一的 `BinaryReflectionSerializer` 反射读写。

生成位置：`Assets/Tools/Scripts/Serialization/Generated/`

### 字段读写

`BinaryReflectionSerializer` 按 `[BinaryField(Order)]` 排序后递归处理字段。已支持的类型：

- 基础值类型（bool、整数、浮点数等）
- `string`
- `enum`
- `T[]`
- `List<T>`
- 嵌套的 `[BinarySerializable]` 类型

不支持的字段类型会抛 `NotSupportedException`。

### null 处理

null 不是被吞掉的默认值，而是显式写入的标记：

| 情况 | 写入 | 读取 |
|------|------|------|
| 引用类型为 null | `hasValue = 0` | 读回 null |
| string 为 null | `hasValue = 0` | 读回 null |
| List / 数组为 null | `count = -1` | 读回 null |

## 使用指南

### 1. 标记数据类型

给类型添加 `[BinarySerializable]` 并设置唯一 Magic 与 SchemaVersion；参与序列化的字段用 `[BinaryField(Order)]` 标记。Order 一旦与已发布数据绑定就不可随意更改。

### 2. 生成序列化代码

菜单：`Tools → Serialization → Generate Binary Serializers`

产物位于 `Assets/Tools/Scripts/Serialization/Generated/{TypeName}_BinarySerializer.cs`。

### 3. 注册类型

在 `BinaryCodec` 注册类型的 Magic、SchemaVersion，以及生成器提供的读写入口。项目类型应集中注册，避免业务代码重复配置。

### 4. 序列化 / 反序列化

通过 `Serialize` 写入字节，通过 `Deserialize<T>` 还原对象。

行为约定：
- `Serialize(null)` 返回空字节数组
- `Deserialize<T>` 遇到非本工具产出的数据返回 `default`
- Magic 不匹配抛 `InvalidDataException`

## 适用场景

**适合**：
- 构建期导出、运行期读取的结构化数据
- 字段结构相对稳定、需要版本控制的数据
- 希望读写紧凑、不依赖第三方库的场景

**不适合**：
- 频繁变动结构、无人维护版本兼容的数据
- 需要跨语言通用的网络协议
- 替代所有 JSON / 配置文件场景

---

## 注意事项

1. **字段顺序不可随意更改**：`[BinaryField(Order)]` 直接决定二进制写入顺序，已落地的数据改顺序会导致读取错位
2. **Magic 不可重复**：Magic 是类型路由的关键，重复会导致数据被错误处理器读取
3. **新增字段要考虑版本兼容**：利用 `SchemaVersion` 做版本判断，不要只改类定义
4. **不支持的字段类型会直接报错**：复杂泛型、Dictionary、自定义容器大概率触发 `NotSupportedException`
5. **生成器有构建前检查**：JSON 可序列化字段缺少 `[BinaryField]` 或生成文件 hash 过期时，Prebuild 会阻断构建

## 常见异常速查

| 异常 | 含义 |
|------|------|
| `InvalidOperationException: 未注册二进制类型` | `Serialize` 前未 `Register` |
| `InvalidOperationException: 未注册的二进制 Magic` | 数据头可读但当前 Codec 未注册该类型 |
| `InvalidDataException: Magic 不匹配` | 数据损坏或类型误判 |
| `InvalidDataException: SchemaVersion 不兼容` | 旧代码读到了更高版本的数据 |
| `NotSupportedException: 不支持的二进制字段类型` | 字段类型超出当前工具支持范围 |
