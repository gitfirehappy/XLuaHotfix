## 概述

项目错误处理采用**两层统一架构**：构建时（`BuildMessage`）和运行时（`RuntimeMessage`）共享相同的设计哲学——`Severity × Code × Message` + 工厂方法。两层类型**有意分离**（不同程序集，运行时无 `Source` 字段），不共享基类。

禁止裸 `new`，所有消息通过静态工厂方法构造。

***

## 架构设计

### 两层分离

```
构建时 (Editor)                              运行时 (Runtime)
─────────────────────                        ────────────────
BuildSeverity { Warning, Error }             RuntimeSeverity { Warning, Error }
BuildMessage {                               RuntimeMessage {
    Severity : BuildSeverity                     Severity : RuntimeSeverity
    Code     : string                            Code     : string
    Message  : string                            Message  : string
    Source   : string                            (无 Source)
}                                            }
工厂方法:                                    工厂方法:
  Error(code, msg, source)                     Error(code, msg)
  Warning(code, msg, source)                   Warning(code, msg)
                                              + 语义化工厂:
BuildErrorCodes (常量)                          NotFound / Ambiguous / TypeMismatch
                                              LoadFailed / BundleNotFound / ...
                                              RuntimeErrorCodes (常量)
```

**为什么分离**：`BuildMessage` 有 `Source`（文件路径/Collector 名，用于 Editor 诊断）；`RuntimeMessage` 没有。强行合并到共享基类属于过度工程。

**为什么 Code 用 string**：经代码审查确认，运行时无任何代码对错误码做 switch 分支。string 允许各模块定义自己的错误码而无需修改中央 enum——与构建时相同的可扩展性收益。

**为什么运行时也有 Warning**：为降级加载、重试恢复等未来消费者预留。目前零个 Warning 消费者，但 Severity 字段成本为零（一个字段），增加它不破坏现有行为。

### 错误码常量

**构建时** (`BuildErrorCodes.cs`)：

| 常量                       | 含义                       |
| ------------------------ | ------------------------ |
| `PATH_NOT_FOUND`         | Collector 路径不存在（Warning） |
| `INVALID_PATH_FORMAT`    | 路径格式不合法                  |
| `DUPLICATE_COLLECT_PATH` | 重复的 CollectPath          |
| `EMPTY_COLLECT_PATH`     | CollectPath 为空           |

**运行时** (`RuntimeErrorCodes.cs`)：

| 常量                        | 含义                               |
| ------------------------- | -------------------------------- |
| `NOT_FOUND`               | 未找到匹配条目                          |
| `AMBIGUOUS_MATCH`         | 多条条目匹配，需 Labels 消歧               |
| `TYPE_MISMATCH`           | PrimaryType 与请求类型不兼容             |
| `LOAD_FAILED`             | 底层加载操作失败                         |
| `INDEX_NOT_SUPPORTED`     | 索引不支持条目级查询                       |
| `BUNDLE_NOT_FOUND`        | Bundle 文件在磁盘上不存在                 |
| `BUNDLE_LOAD_FAILED`      | AssetBundle.LoadFromFile 返回 null |
| `DEPENDENCY_FAILED`       | 依赖 Bundle 加载失败                   |
| `ASSET_EXTRACTION_FAILED` | 从 Bundle 提取 Asset 失败             |

### Severity 判定规则

- **Error** = 结果不正确/不完整，继续执行会产生错误输出
- **Warning** = 检测到异常但不影响受影响资产之外的正确性

`PATH_NOT_FOUND` 是 Warning 而非 Error：该目录缺失意味着此 Collector 收集零个资产，同一 Package 内其他 Collector 可能正常。Package 结果只会缺少这些资产，不会被污染。

## 使用指南

### 构建时：创建 BuildMessage

```csharp
// Error —— 阻塞构建
var err = BuildMessage.Error(
    BuildErrorCodes.DUPLICATE_COLLECT_PATH,
    "重复的 CollectPath",
    collectorPath);

// Warning —— 报告但不阻塞
var warn = BuildMessage.Warning(
    BuildErrorCodes.PATH_NOT_FOUND,
    $"路径不存在: {path}",
    collectorPath);
```

`ScanResult` 收集 `List<BuildMessage>`，通过 `HasErrors` 属性判断是否有 Error 级别消息。

### 运行时：创建 RuntimeMessage

**通用工厂**：

```csharp
var err = RuntimeMessage.Error("MY_CODE", "描述信息");
var warn = RuntimeMessage.Warning("MY_CODE", "描述信息");
```

**语义化工厂（推荐）**：

```csharp
// 未找到
RuntimeMessage.NotFound("key_or_query");

// 多条匹配（带候选列表）
RuntimeMessage.Ambiguous("query", candidatesList);

// 类型不匹配
RuntimeMessage.TypeMismatch("query", "期望类型", "实际类型");

// 加载失败
RuntimeMessage.LoadFailed("entryId", "失败原因");

// Bundle 相关
RuntimeMessage.BundleNotFound("bundleName");
RuntimeMessage.BundleLoadFailed("bundleName", "/path/to/bundle");
RuntimeMessage.DependencyFailed("mainBundle", "depBundle");

// Asset 提取失败
RuntimeMessage.AssetExtractionFailed("entryId", "sourcePath", "bundleName");
```

### 公开 API 错误契约

所有 `IPackageBackend` 加载方法返回 `(T, RuntimeMessage)` 元组，**不抛异常**：

```csharp
// 异步
var (asset, error) = await backend.LoadAssetAsync<Texture2D>("myKey");
if (error != null)
{
    Debug.LogError(error.ToString());  // 输出 "[NOT_FOUND] 未找到匹配条目: myKey"
    return;
}
// 使用 asset...

// 同步
var (asset, error) = backend.LoadAssetSync<GameObject>("myPrefab");
if (error != null) return;
```

### Handle 路径错误传播

通过 `AssetPackageManager.LoadByAddress<T>()` 等 Resolve-And-Handle API 加载时，错误通过 `AssetHandle<T>` 传播：

```csharp
var handle = await AssetPackageManager.Instance.LoadByAddress<Texture2D>("myTex");
if (!handle.IsValid)
{
    Debug.LogError(handle.Error.ToString());  // RuntimeMessage 来自 Resolve 或 Load 阶段
    return;
}
// 使用 handle.Asset...
handle.Release();
```

`HandleRegistry` 存储每个 Slot 的 `RuntimeMessage`，`AssetHandle<T>.Error` 属性直接读取。成功加载时 Error 为 null。

### FileHelper 错误语义

| 方法                                           | 错误行为                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------- |
| `ReadAllBytesAsync` / `ReadAllTextAsync`     | 抛 `FileNotFoundException`（文件不存在）或 `IOException`（Android StreamingAssets 读取失败） |
| `WriteAllBytesAtomic` / `WriteAllTextAtomic` | 抛 `ArgumentNullException`（参数为 null）或 I/O 异常                                   |
| `TryDelete` / `TryDeleteDirectory`           | **永不抛异常**，失败返回 `false` + `Debug.LogWarning`                                   |

## 注意事项

1. **只用工厂方法，禁止裸 new**：`RuntimeMessage` 和 `BuildMessage` 的构造函数是 `private`。所有构造必须通过工厂方法。这保证 Code 字段始终使用常量、Message 格式一致。
2. **Code 用** **`RuntimeErrorCodes`** **/** **`BuildErrorCodes`** **常量**：不要在调用点硬编码 `"NOT_FOUND"` 字符串。新增错误码先在对应的 Codes 文件中添加 `const string`。
3. **不要跨层混用**：运行时代码不应引用 `BuildMessage` / `BuildSeverity`（在 Editor 程序集中）。构建时代码不应创建 `RuntimeMessage` 用于构建诊断。两层类型有意分离。
4. **Warning 预留，暂不主动使用**：运行时 `RuntimeSeverity.Warning` 已定义且工厂方法可用，但当前无消费者。只有在确实需要"成功但不理想"语义时才使用——不要为了用而用。
5. **公开 API 不抛异常**：`IPackageBackend` 的所有实现（`ABPackageBackend`、`AddressablesBackend`）必须将错误作为 `RuntimeMessage` 返回，不抛出。调用方检查 error 字段。内部方法（`LoadAssetInternal*`）也遵守此约定。
6. **`(T, RuntimeMessage)`** **元组的错误组合**：error != null 时 asset 为 null；error == null 时 asset 保证非 null。调用方可仅检查 error。
7. **HandleRegistry 引用计数保护**：同一 EntryId 的多个 Handle 共享 `_entryActiveCounts` 计数。Release 回调仅在计数归零时触发——防止 use-after-free。不要绕过 Handle 直接调用 `UnloadAsset`/`UnloadByEntryId`（除非你确认没有活跃 Handle）。
8. **FileHelper 原子写入的临时文件**：`WriteAllBytesAtomic` 使用 `{path}.tmp.{guid8}` 格式的临时文件。写入成功后 rename 到目标。如果 rename 前进程崩溃，临时文件残留可作为恢复产物（不自动清理）。
