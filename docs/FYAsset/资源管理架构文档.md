## 设计目标

FYAsset 在保留 Addressables（AA）生产链的同时，建设自研 AssetBundle（AB）链。两条后端共享版本、构建编排、仓库、热更状态机和错误模型，但各自拥有独立配置、构建入口、运行时后端和发布目录。

旧 public 类型作为兼容门面保留；新代码优先使用明确的 AA/AB concrete 入口，避免运行时依赖全局开关。

---

## 分层

代码根目录只表达三种所有权：

| 根目录 | 责任 |
|--------|------|
| `AA/` | Addressables 专属构建、manifest、热更后端和运行时入口 |
| `AB/` | Collector、依赖分析、自研 Bundle 构建、ABManifest 和 AB 运行时 |
| `Shared/` | 后端无关契约、版本、Pipeline、Repository、热更编排、路径和兼容门面 |

Editor 代码负责扫描、构建、预览和发布；Runtime 代码只依赖已导出的 BuildIndex、PackageIndex、manifest 与 Bundle。运行时代码不得反向引用 Editor 程序集。

---

## 端到端流程

| 阶段 | 输入 | 输出 | 核心保证 |
|------|------|------|----------|
| 1. 采集 | Collector 与 AssetEntry | `CollectedAssetInfo` | GUID 身份稳定；Address/Labels 语义明确 |
| 2. 依赖 | 已采集资产 | 共享抽取结果与 Bundle 图 | 依赖可达、无错误跨包重叠 |
| 3. 构建 | 线性 Task 配置 | Bundle、manifest、校验结果 | Fatal 立即中止；预览不污染正式输出 |
| 4. Repository | 当前产物指纹 | object、HEAD、CommitDelta | object 与 HEAD 原子提交；AA/AB Channel 隔离 |
| 5. Push | 已提交 HEAD 包体 | 后端发布根与 PackageIndex | 包目录与指针同事务；Push 不暗改运行时 URL |
| 6. Hotfix | BuildIndex、本地/远端 PackageIndex | 已校验并激活的本地内容 | 未完整内容不激活；本地 PackageIndex 最后写 |
| 7. Runtime | 当前 manifest 与 Bundle | Asset 或 `AssetHandle<T>` | 结构化错误、引用计数和依赖卸载 |

## AA 与 AB 的边界

| 维度 | AA | AB |
|------|----|----|
| 定位系统 | Addressables catalog | ABManifest 索引 |
| manifest 角色 | AAManifest 提供版本、校验和查询索引 | ABManifest 同时提供资产、Bundle 和依赖映射 |
| 构建 | Addressables BuildPlayerContent | Collector → 依赖分析 → AssetBundle Build |
| 运行时加载 | Addressables API | `ABPackageBackend` / `ABBundleLoader` |
| 引用管理 | Addressables Handle | Asset + Bundle 双层计数，外加 `AssetHandle<T>` |
| 发布根 | `/AA/` | `/AB/` |

AA/AB 可以同时构建和查看 Repository；`UseABBackend` 只保留给旧兼容入口与命令行路由。

---

## 核心模型

| 模型 | 作用 |
|------|------|
| `VersionNumber` | 定义发布身份与 Major 兼容边界 |
| `BuildIndexData` | 描述安装包内置基线 |
| `PackageIndex` | 指向远端目标包或本地最近成功激活包 |
| `ManifestAssetEntry` | 记录资产身份、Address、类型、Labels 与 Bundle 归属 |
| `ManifestBundleEntry` | 记录 Bundle 校验信息、依赖和策略 Tags |
| `AAManifest` / `ABManifest` | 描述对应后端的包体元数据 |
| `RuntimeMessage` | 统一运行时失败语义 |
| `AssetHandle<T>` | 管理 AB 资产所有权和错误传播 |

字段级语义见[字段语义参考表](./字段语义参考表.md)，本文不复制源码。

## 三类路径

- URL 使用 `JoinUrl`，保证斜杠和后端根语义正确。
- 本地文件系统使用 `JoinFilePath/ResolveFilePath`，处理相对根与平台分隔符。
- Unity AssetDatabase 路径保持 `Assets/...`，使用 `NormalizeAssetPath/JoinAssetPath`。

Android StreamingAssets 的 `jar:` 路径属于 URI-like 路径，不能按 Windows 本地盘符处理。

---

## 关键安全边界

- 版本只在构建与 Repository commit 都成功后写回。
- PackageIndex 等可见指针只在对应包体和仓库状态就绪后发布。
- Diff Preview 只读，不写 HEAD、objects、正式 PackageIndex 或正式输出。
- Hotfix 下载先进入 `.tmp`，校验通过后替换；未完整的目标 Hotfix 包不得写入本地 PackageIndex。
- AA/AB 配置、Repository Channel、PackageIndex 与发布根必须隔离。
- 公开加载 API 返回结构化错误；清理与回滚路径不得掩盖主失败。
