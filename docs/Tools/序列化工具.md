# 通用序列化工具

> **关联代码** | [Serialization](../../Assets/Tools/Scripts/Serialization/)

工具提供 JSON 与带头部的 Binary 编解码、类型注册、字段反射读写和 Editor 生成器。工具不知道任何业务 Manifest、包或构建后端；消费方负责类型、Magic、schema 和初始化时机。

## 调用与格式

`SerializationUtility` 注册 JsonCodec 与 BinaryCodec。Serialize 默认 JSON，指定 `binary` 才走二进制；Deserialize 可显式指定 codec，或按已注册 Magic 探测。没有注册的 Magic 不会被自动识别为 Binary，因此必须先注册业务类型，再自动探测数据。

BinaryHeader 为 8 bytes：uint Magic、ushort SchemaVersion、ushort Flags。Codec 拒绝高于已注册版本的 schema；生成包装器要求与声明版本一致。该检查不会自动迁移旧布局。

BinaryReflectionSerializer 按 BinaryField.Order 递归处理基础数值、bool、string、enum、数组、List 和标记的嵌套 class/struct。不支持的字段抛 NotSupportedException；它不是任意对象图、循环引用或跨语言协议工具。

| 数据 | 表示 |
|---|---|
| null class | 存在标记为 false |
| 非 null class | 存在标记后写字段 |
| struct | 直接写字段，不写引用存在标记 |
| null string | 存在标记为 false |
| null List/数组 | 长度 -1 |
| 空 List/数组 | 长度 0 |

BinaryCodec.Serialize 的根 null 返回空字节；不足一个 header 的直接 Binary Deserialize 返回 default。该行为不能扩展为“所有损坏数据都返回 default”，字段读取、Magic、schema 或类型错误仍可抛异常。

## 定义与生成

```csharp
[BinarySerializable]
public struct SampleData
{
    [BinaryField(0)] public int Id;
    [BinaryField(1)] public string Name;
}
```

生成器由调用方传入类型集合与输出目录：

```csharp
BinarySerializerGenerator.GenerateAll(
    new[] { typeof(SampleData) },
    "Assets/MyModule/Generated");
```

输出是类型级 header 包装器，底层仍调用反射序列化器，并非无反射 AOT 字段展开。调用方用 `BinaryCodec.Register<T>` 注册包含 header 的读写委托。生成器不应清空目标目录或删除已有 `.meta`。

## 所有权与验证

工具层不包含业务注册器和业务生成文件。FYAsset 的 Binary 注册与生成类位于 `Assets/FYAsset/Scripts/Compat/Serialization/`。JSON 版本字段是否存在由 FYAsset 读取边界检查，不是 JsonCodec 的行为。消费项目可设置 Editor 菜单、运行时初始化和 prebuild check。

class 改 struct 会改变存在标记，即使字段 Order 不变也不兼容。修改 schema 必须考虑嵌套类型；当前字段 hash 不能完整发现所有递归布局变化，也不提供自动迁移。旧数据兼容必须由消费方明确选择。

`WriteToFile` / `WriteToFileAsync` 使用直接文件写入，不能视为原子替换。Android StreamingAssets URI 读取应走平台 I/O 工具，不能直接把 URI 交给 File.ReadAllBytes。

隔离行为测试位于 `tests/scenario/serialization/`，覆盖 class/struct 复制、解析比较、嵌套空值，以及 JSON 对象字段存在性。纯 .NET 测试不证明 Unity JsonUtility、IL2CPP stripping 或真实 Editor 生成流程均已验证。
