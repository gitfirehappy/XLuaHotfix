# C# 注释规范（FYAsset）

本文约束 FYAsset 与通用序列化工具的手写 C# 注释；生成代码通过生成模板治理。通用协作规则见 AGENTS.md；当前架构与实现说明放 `docs/`。

## 总原则

- 注释描述代码可被验证的事实：职责、约束、所有权、生命周期、调用顺序、失败条件、副作用。
- 注释是否保留按信息价值判断，不要求公开成员 100% 覆盖 XML 注释；名称已充分表达的成员可以没有注释。
- 禁止复述签名与逐行逻辑、写实现历史或开发叙事、写未在代码实现的“预留功能”、写主观评价（优雅/健壮/简单等）。
- 删除或修改代码时同步删除失实注释；宁可无注释，不要过期注释。
- 真实标识符与既定术语（GUID、Manifest、Bundle、Editor、Runtime、CLI、URL）保留英文。可用简短英文准确表达的说明使用英文；复杂约束与原因使用简体中文并保留英文术语。
- 不强制每个文件包含 XML 注释或 `region`。逐文件核查注释与实际代码的一致性；格式检查和编译不能替代语义核查。

## XML 文档注释

- `<summary>` 说明“做什么”与必要的“何时调用”，控制在两句短句以内。
- `<remarks>` 只放契约事实：所有权、生命周期、单位、线程归属、异常与失败语义；每条事实一句，最多三句。
- 类型与成员名在叙述中用纯文本；仅歧义时才用 `<see cref="..." />`；参数引用用 `<paramref name="..." />`。
- 泛型参数名用花括号形式，如 `AssetHandle{T}`；链接人类文档使用相对路径纯文本。

## 行内与块注释

- 只为非直观行为写：状态转换的隐含前提、资源释放的先后要求、外部副作用（文件/网络/进程）、防御边界存在的原因。
- 私有辅助方法的重复逻辑、变量用途明显时不写。
- 不使用“temp/TODO 占位/本期未实现故事”式注释；限制影响调用者时，直接写当前行为。
