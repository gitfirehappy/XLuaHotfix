# Plan: Assets Collection Follow-up Fixes

> Status: Signed off / Archived
> Date: 2026-06-05
> Requirement ID: assets-collection-followup-20260605
> Scope: Project Scan Scene folder cleanup, long-path Address semantics, and asset exclusion ownership/UI.

## Goal

Fix the acceptance feedback from the AssetsCollection cleanup:

- Project Scan must not create a folder-level Collector for Scene-only folders such as `Assets/Scenes`.
- Long-path Address generation must keep the asset file suffix.
- Asset-level exclusions must be owned by `AssetCollectionSetting`, managed next to scan Ignore rules, and readable by asset path/object reference instead of opaque GUID strings.

## Root Causes

1. Project Scan creates Folder Collectors whenever `HasCollectableAssets(folder, IgnorePatterns)` sees any file. `.unity` files satisfy that check, so `Assets/Scenes` is added as a Folder Collector before Scene File Collectors are appended.
2. `AssetAddressGenerator.GenerateLongAssetPath()` intentionally strips the extension, so long-path Address currently outputs `Assets/.../Name`.
3. `FYAssetABSettings.ExcludedAssetGUIDs` stores only GUID strings in backend config, making exclusions hard to inspect and placing asset collection state outside the same data owner as `IgnorePatterns`.

## Decisions

1. Scene assets stay file-owned. Folder Collectors generated by Project Scan should represent non-Scene assets only.
2. `LongAssetPathWithoutExtension` keeps its serialized enum name for compatibility, but its current behavior changes to long Unity asset path with extension.
3. Exclusions move to `AssetCollectionSetting.ExcludedAssets`, represented as entries with `AssetGUID` and cached `AssetPath`.
4. `FYAssetABSettings.ExcludedAssetGUIDs` remains only as a legacy migration input and is removed from active AB Config UI.
5. The Ignore panel becomes the collection filter/exclusion management surface: scan ignore patterns plus excluded assets.

## Implementation Checklist

1. Data model and migration
   - Add `AssetExclusion` to `AssetCollectionSetting`.
   - Add helper methods to find/add/remove exclusions by GUID and refresh cached paths from `AssetDatabase`.
   - Update clone/save paths to preserve `ExcludedAssets`.
   - Migrate legacy `FYAssetABSettings.ExcludedAssetGUIDs` into the loaded `AssetCollectionSetting` when present, then clear the legacy list after successful transfer.
2. Scanner and reverse index
   - Change `CollectionScanOptions.FromABSettings()` to read exclusions from `AssetCollectionSetting`.
   - Update `TaskCollectAssets`, Curate, Project Scan, and preview scans to pass the current setting-owned exclusions.
   - Update `CollectorReverseIndex` and `CollectorMutationUtility` to read/write `AssetCollectionSetting.ExcludedAssets`.
3. Project Scan
   - Change folder generation so a folder gets a Folder Collector only if it contains at least one non-Scene collectable asset after ignore filtering.
   - Keep `.unity` assets as File Collectors with Scene payload.
   - Normalize old Scene-only Folder Collectors in Curate before save, and make scanner skip `.unity` from Folder Collectors as a build-time guard.
4. Address generation
   - Change long-path Address generation to preserve the extension.
   - Rename UI labels/docs from "Long path without extension" wording to long path with extension where applicable, while keeping enum name for serialized compatibility.
5. Exclusion UI
   - Remove `ExcludedAssetGUIDs` from AB Config.
   - Add an Excluded Assets section next to Ignore Patterns.
   - Show each exclusion as an object/path-aware row with Select, Ping, Replace, and Remove behavior when the asset resolves.
6. Verification
   - `dotnet build XLuaHotfix.sln --no-restore`
   - `git diff --check`
   - Static searches:
     - Project Scan folder collectors do not use Scene-only folders.
     - Active exclusion reads come from `AssetCollectionSetting`, not `FYAssetABSettings`.
     - AB Config no longer exposes `ExcludedAssetGUIDs`.
     - Long-path Address generation keeps extension.

## Non-Goals

- Do not change runtime loading APIs.
- Do not change Lua bridge behavior.
- Do not add per-Collector exclusion lists.
- Do not manually rewrite existing collector data except through the approved model/migration path.
