# FYAsset 自动化测试管线

> **关联代码** | `CommandLine/fyasset_test.py` · `CommandLine/fyasset_reset.py` · `CommandLine/run_fyasset_test_batch.py` · `Assets/FYAsset/Scripts/Compat/Editor/Tests/Editor/`

## 概述

Build 侧与 E2E 侧共用 CLI 表面，对 AA/AB 的 Full / Hotfix / Chain，以及 AB Standalone 做可恢复的自动化验收。正式资源构建入口仍是 `BuildCommandLine`；本管线是验收层，不替代发版构建。

```text
fyasset-test aa|ab build|e2e full|hotfix|chain --target <id> [--target <id>...]
fyasset-test ab e2e standalone
```

外部 Target 额外需要：

```text
--confirm-external-publish <id>
```

Editor 人工测试的唯一入口是 AA/AB Build Pipeline 内部的 `Test` 面板；顶部 `FYAsset/Tests/*` 菜单已移除。面板只为真实 Push Target 显示勾选项（当前为 `local`、`cloudflare`），不再额外显示 External confirmation 勾选。选择外部 Target 后执行测试时弹出一次确认，确认结果自动传给引擎；AB Editor PlayMode Smoke 也从该面板触发。

## 前置条件

| 条件 | 说明 |
|------|------|
| 关闭 Unity Editor | `fyasset_test.py` 检测到 `Unity.exe` 会 exit 3 |
| `CommandLine/build.config` | 配置 `UnityPath=` |
| Push Target | Full/Hotfix/Chain 需要 Settings 中可解析的 `--target` id（常用 `local`） |
| 永久夹具 | `Assets/Test/FYAssetPipeline/` 已入组，测试不临时创建 Group |

## 模式语义

| 模式 | 项目初始 | 序列 | 用途 |
|------|----------|------|------|
| Full | 隔离 `1.0.0` + 清空该后端 Repository | Full → `2.0.0` | 聚焦 Full + 发布 |
| Hotfix | 优先复用已有 `LatestFull`；无 Full 基线时在事务内 seed Full | Fixture 变更 → Hotfix | 聚焦 Hotfix + 发布 |
| Chain | 同 Full 隔离 | Full → fixture → Hotfix | 权威 Full→Hotfix 链路 |
| Standalone | AB only；不依赖 Target / 本地热更服 | BuildStandalone → bake `StandaloneBuild=true` Player → exit 0 | 离线包路径隔离验收 |

E2E 在 Build 事务之上追加 Windows Player 构建与协调器冒烟。`ab e2e standalone` 不走 CDN/本地热更服，产物直接生成到 `StreamingAssets/Standalone/`，与在线基线 `StreamingAssets/bundles/` 物理隔离；`HotfixOutput/Packages/` 不生成同名副本。

## 清空重置

每个独立用例前建议执行：

```bash
python CommandLine/fyasset_reset.py all --keep-testruns --reports --clear-publish
```

批量脚本 `CommandLine/run_fyasset_test_batch.py` 已内置「每用例先 reset」。

重置范围（仅 project-local）：

- `BuildData/Baselines`、可选 Reports
- `HotfixOutput/Packages`、PackageIndex
- StreamingAssets 导出物
- VersionRecord → `1.0.0 / Build 0`
- 永久夹具 marker 回到 v1
- 可选 Local/Cloudflare 发布树

## 串行批量

```bash
python CommandLine/run_fyasset_test_batch.py
```

产物：

- `HotfixOutput/TestRuns/cli-batch-3/<case>.stdout.log`
- `HotfixOutput/TestRuns/cli-batch-3/<case>.result.json`
- `HotfixOutput/TestRuns/cli-batch-3/summary.json`
- 引擎侧 `HotfixOutput/TestRuns/{AA|AB}/{build|e2e}/{mode}/<runId>/result.json`

## 退出码（测试引擎）

| 码 | 含义 |
|----|------|
| 0 | 通过 |
| 7 | 前置条件失败（历史：无 Full baseline；现 seed 后应减少） |
| 8 | 构建失败 |
| 9 | 运行时 / Player 失败 |
| 其它 | 发布/探测/恢复失败等，见 `result.json` |

CLI 包装额外：2 参数无效、3 Editor 占用、130 中断。

## Player 持久化隔离

Standalone Player 无可靠 `-persistentDataPath` CLI。E2E 通过临时改写 `FYAssetSettings.ProjectName` 并 bake 进 Player，使 `LocalLow/{company}/{product}/{isolatedProjectName}` 与开发机 `fyasset` 缓存隔离；结束后恢复 SO 并删除隔离目录。

## 与正式构建的边界

| 关注点 | 正式构建 CLI | 测试管线 |
|--------|--------------|----------|
| 入口 | `BuildCommandLine.Build` | CLI：`BuildTestCommandLine` / `E2ETestCommandLine`；Editor：管线内部 `Test` 面板 |
| 后端选择 | `FYAssetBackendSettings` 资产（Compat 统一入口） | 显式 `aa` / `ab`，不跟随宿主选择配置 |
| Target | 人工 / 仓库推送 | 强制 `--target`，可多 Target |
| 恢复 | 不保证 | 始终尝试 restore project + Target |

## 已知残差

1. FYAsset 尚未拆独立 asmdef（架构项，见 review）。
2. Cloudflare / 多 Target 需额外确认参数，不在默认 batch 内。

## Player 前向热更（已落地）

`e2e hotfix` / `e2e chain`：

1. Full 发布 → 构建 Player → Full smoke（干净隔离 persistent）  
2. 保留同一 Player 二进制 + 同一 `ProjectName` 隔离目录  
3. Hotfix 构建并发布 → **relaunch 同 Player** → coordinator 校验 v2 marker  

## 收尾人工验收流程

自动化结果只证明脚本路径通过；以下流程用于确认 Unity 编辑器交互、Editor PlayMode、Standalone Player 和最终恢复状态。除 A0/A10 外，每个用例都应记录 `result.json`、Unity Console 或 Player 日志，并在失败后停止后续用例。

| 编号 | 范围 | 操作 | 通过标准 |
|---|---|---|---|
| A0 | 准备 | 关闭 Unity；确认使用 `local` Target；执行 `python CommandLine/fyasset_reset.py all --keep-testruns --reports --clear-publish` | 测试状态干净，不使用外部 Target 或 Cloudflare |
| A1 | 编译 | 打开项目，等待导入和 Domain Reload，检查 Console、测试菜单和 Settings | 无编译错误、无未处理异常；测试菜单可见 |
| A2 | Settings | 分别切换 `AB Editor PlayMode` 与 `Package Mode`，关闭并重新打开 Settings | 两组设置互不覆盖并可持久化；`Simulate` 明确按 Runtime 处理 |
| A3 | AB Editor PlayMode | 打开 AB Build Pipeline 的 `Test` 面板，执行 `Editor PlayMode Smoke`；必要时重载 Domain | 出现 `[EditorPlayModeSmoke] PASS`，`FYAssetPipelineSync` 加载成功 |
| A4 | AB Runtime 回归 | 切回 `PlayMode=Runtime`，进入 Play Mode，加载异步 SO、同步 Text 和 Lua | 走真实 AB 路径；资源可加载；无 AA/AB 混用或结构化错误 |
| A5 | AA Build | 关闭 Unity 后依次运行 `python CommandLine/fyasset_test.py aa build full --target local`、`python CommandLine/fyasset_test.py aa build hotfix --target local`、`python CommandLine/fyasset_test.py aa build chain --target local` | Full、Hotfix、Chain 通过；Target、Repository、PackageIndex 和项目状态恢复 |
| A6 | AB Build | 依次运行 `python CommandLine/fyasset_test.py ab build full --target local`、`python CommandLine/fyasset_test.py ab build hotfix --target local`、`python CommandLine/fyasset_test.py ab build chain --target local` | AB Manifest、Bundle、RawFile、Lua 映射正确；Full → Hotfix 链路通过 |
| A7 | Standalone | 记录 `HotfixOutput/Packages/` 现有目录，运行 `python CommandLine/fyasset_test.py ab e2e standalone`，再检查 Player、`StreamingAssets/Standalone/` 和 Packages | Player 退出码为 0；不请求热更服务；离线包只存在于 Standalone 目录；Packages 未新增对应 `BuildGUID` 目录 |
| A8 | E2E 连续热更 | AA、AB 分别运行 `python CommandLine/fyasset_test.py <aa|ab> e2e <full|hotfix|chain> --target local` | Hotfix/Chain 复用同一 Player 和持久化目录，并出现 v2 marker |
| A9 | 失败恢复 | 使用无效 Target、无 Full 基线的 Hotfix，必要时中断一次运行 | 返回明确失败码；不残留 Player、服务器、端口或半成品 Target |
| A10 | 收尾 | 关闭 Unity、Player、服务器；运行 `git diff --check` 并检查 `git status` | 无进程残留；证据已归档；计划和进度已同步；提交后工作区干净 |

Android Standalone 不在本轮验收范围内；当前已知限制是 Android StreamingAssets Bundle 加载尚未支持。
