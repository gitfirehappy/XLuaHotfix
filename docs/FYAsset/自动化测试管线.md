# FYAsset 自动化测试入口

> **关联代码** | [FYAsset Tests](../../Assets/FYAsset/Scripts/Tests/) · [fyasset_test.py](../../CommandLine/fyasset_test.py) · [fyasset_reset.py](../../CommandLine/fyasset_reset.py) · [隔离场景](../../tests/scenario/)

测试分为隔离代码场景、Unity 构建测试和 Player E2E。它们验证的范围不同，不以一个 PASS 覆盖全部框架行为。正式构建入口仍是 BuildCommandLine.Build。

## 低副作用验证

- `node tests/scenario/serialization/run.mjs`：使用已安装 .NET 编译器，验证 VersionNumber 值复制和通用 Binary class/struct/嵌套/空值，不执行 Unity 或网络操作。
- `tests/scenario/s3_resource_boundary`：源码边界门禁。Labels 检查的是候选修改与 Save/Cancel 的源码结构，不等于 Unity 交互测试。
- `tests/scenario/runtime_resource`：受控 Unity/Addressables 替身下的资源生命周期场景，不加载真实 Bundle。
- 解决方案编译只证明当前编译输入可通过，不能证明导出依赖完整、UI布局正确或运行资源可加载。

## Unity 与 E2E

Editor 入口是独立 Test Matrix 窗口，源码为 Tests/Editor/Build/BuildTestWindow.cs；不再描述为旧 Repository 内嵌 Test 页。CLI 由 BuildTestCommandLine 与 E2ETestCommandLine 提供，Python 包装器支持显式 AA/AB、build/e2e、full/hotfix/chain；AB 另有 standalone 路径。

示例仅用于获准的隔离环境：

```text
python CommandLine/fyasset_test.py ab build chain --target local
python CommandLine/fyasset_test.py ab e2e standalone
```

这些命令会构建资源、修改项目状态，并可能发布到目标；不能当作日常只读检查。外部目标必须明确确认。运行前核对 build.config 中的 UnityPath、目标配置、已有数据和 Editor 占用情况。

## 模式

| 模式 | 主要行为 |
|---|---|
| Full | 准备测试状态后构建 Full，并验证交付/目标 |
| Hotfix | 使用或准备 Full baseline，修改 fixture 后构建 Hotfix |
| Chain | Full、fixture 变更、Hotfix 连续链 |
| E2E | 在构建测试基础上生成并运行 Player；前向更新可复用同一 Player 与隔离持久化目录 |
| Standalone | AB 离线输出交付到 StreamingAssets/Standalone，不要求在线发布目标 |

精确序列以 BuildTestEngine/E2ETestEngine 的当前实现为准。原 `run_fyasset_test_batch.py` 不存在，不再提供其调用或虚构批量结果目录。

## 重置与恢复

`fyasset_reset.py` 是破坏性维护入口，不建议在每次测试前无条件执行。它可能修改 VersionRecord、清除 baseline/包/启动数据/报告/发布目录；调用前必须明确所选参数与范围。

测试引擎会尝试恢复项目与目标，但恢复也可能失败。需要检查 result.json、日志、目标身份、临时配置以及残留进程。不要以退出码为零替代人工核对恢复状态，不清理未属于当前测试的目录或进程。

## 必须单独验收的行为

1. Unity Domain Reload、窗口切换、窄窗口与长路径布局。
2. Collection Labels 编辑、整批拒绝、Save、Cancel 和未保存提示。
3. 真正的 AA/AB Full/Hotfix 产物、完整 Manifest 与累计交付。
4. Player 加载、RawFile、Lua 索引、并发获取和释放。
5. 下载失败、激活失败、版本异常、索引写入和恢复失败。
6. Android StreamingAssets 与独立导出工程，不能由桌面 stub 测试推断。

BuildTestAcceptance 中部分 AB Address 检查使用字符串与文件名启发式，不证明运行时可解析；这属于已有验证缺口。历史结果与待验收项保留在 requirements，不在本指南复制为当前通过状态。
