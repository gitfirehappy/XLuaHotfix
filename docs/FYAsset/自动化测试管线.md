# FYAsset 自动化测试入口

> **关联代码** | [FYAsset Tests](../../Assets/FYAsset/Scripts/Tests/) · [fyasset_test.py](../../CommandLine/fyasset_test.py) · [fyasset_reset.py](../../CommandLine/fyasset_reset.py) · [隔离场景](../../tests/scenario/)

测试分为隔离代码场景、Unity 构建测试和 Player E2E。它们验证的范围不同，不以一个 PASS 覆盖全部框架行为。正式构建入口仍是 `BuildCommandLine.Build`。

## 隔离场景工程与退出码约定

`tests/scenario/` 下的每个工程都是独立可执行的 .NET 控制台程序，**不在 `XLuaHotfix.sln` 内**，各自用 `dotnet run --project <csproj>` 执行。退出码约定统一为：

| 退出码 | 含义 |
|---|---|
| `0` | 全部门禁/断言通过 |
| `1` | 存在失败门禁、断言失败，或没有任何断言被执行 |

场景只读源码或使用临时目录，禁止访问网络。

| 场景工程 | 执行命令 | 输出与规模 |
|---|---|---|
| `pipeline_realignment` | `dotnet run --project tests/scenario/pipeline_realignment/PipelineRealignmentTests.csproj` | 7 个门禁（T0/T1/T2/T4/T6/T7/T8 契约）；末尾打印 `pipeline realignment gates: N/7 passed` |
| `build_cache` | `dotnet run --project tests/scenario/build_cache/BuildCacheTests.csproj` | 5 组 59 条断言（指纹稳定性、历史制品复用、复用依赖闭合、内容逻辑名规则、依赖下标等价）；打印 `build cache assertions: P/T passed` 与 `build cache scenario groups: N/5 passed` |
| `pipeline_compose` | `dotnet run --project tests/scenario/pipeline_compose/PipelineComposeTests.csproj` | 4 组 29 条断言；打印 `pipeline compose assertions: P/T passed` 与 `pipeline compose scenario groups: N/4 passed` |
| `publish_diff` | `dotnet run --project tests/scenario/publish_diff/PublishDiffTests.csproj` | 6 个场景（FileDiff 分类、发布事务决策、目标包组装决策、Cloudflare 发布回滚、发布路径 containment、旧包清理规则）；打印 `publish diff scenarios: N/6 passed` |
| `ab_remediation` | `dotnet run --project tests/scenario/ab_remediation/AbRemediationTests.csproj` | 6 个门禁（Summary 所有权与事务、包纯度、物理命名、Hotfix 候选与交付基准）；打印 `ab remediation gates: N/6 passed` |
| `s3_resource_boundary` | `dotnet run --project tests/scenario/s3_resource_boundary/S3ResourceBoundaryTests.csproj` | 源码边界门禁（含后端标签面板与导出边界） |
| `runtime_resource` | `dotnet run --project tests/scenario/runtime_resource/RuntimeResourceScenarioTests.csproj` | 受控 Unity/Addressables/Scene 替身下的资源生命周期与公共索引场景，不加载真实 Bundle |
| `HotfixRuntimeStateMachineTests` | `dotnet run --project tests/scenario/HotfixRuntimeStateMachineTests.csproj` | 热更状态机与失败矩阵场景 |
| `S2RuntimeBoundaryTests` | `dotnet run --project tests/scenario/S2RuntimeBoundaryTests.csproj` | S2 运行时边界场景 |

各场景的分组名与断言名会逐条打印（`PASS` / `GREEN` 与 `FAIL` / `RED`），失败信息带定位上下文。

### 场景覆盖范围

| 场景 | 锁定的契约 |
|---|---|
| `pipeline_realignment` | Shared 不引用 AA/AB 类型、公共 Address 唯一与 Public 边界、RawFile 白名单与共享策略、Manifest 结构、Runner/Composer 主干与自定义 Task、旧机制退出（T7 门禁断言 Repository 与 baseline 语义已删除）、Hotfix 单包根与运行时 Check/Prepare/Apply |
| `build_cache` | 输入指纹稳定性、按正式 Summary 索引的历史制品复用与失效矩阵、复用依赖事实回放与闭合裁剪、内容逻辑名/物理名规则、复用+重建混合构建的依赖下标等价 |
| `pipeline_compose` | Composer 组装顺序与全部装配失败分支、Runner 的 pending/running/success/skipped 状态、失败即停、attempt 提升与交付 token |
| `publish_diff` | `FileDiff` 分类、发布事务的复用/退化/不可变目录决策、目标包组装（稀疏 Hotfix 与来源不足）、Cloudflare 失败回滚、发布路径 containment、旧包清理规则 |
| `ab_remediation` | Summary 是构建事实唯一拥有者且 Index 可重建、包目录只含发布内容、物理命名（12 位身份 hash 与 kind 段）、Hotfix 单包根修复与基准 Full 差异交付 |

## Node 场景

```text
node tests/scenario/serialization/run.mjs
```

使用本机已安装的 .NET SDK 与 Roslyn 编译 `tests/scenario/serialization/scenarios.cs` 与 `VersionNumber` + 通用二进制序列化源码，验证值复制、class/struct/嵌套/空值与 header 行为；不执行 Unity 或网络操作。退出码沿用编译或运行结果。

## Unity 与 E2E

Editor 入口是独立 Test Matrix 窗口（`Tests/Editor/Build/BuildTestWindow.cs`，面板实现为 `BuildTestPanel`）。CLI 由 `BuildTestCommandLine` 与 `E2ETestCommandLine` 提供，Python 包装器支持显式 AA/AB、build/e2e、full/hotfix/chain；AB 另有 standalone 路径。

示例仅用于获准的隔离环境：

```text
python CommandLine/fyasset_test.py ab build chain --target local
python CommandLine/fyasset_test.py ab e2e standalone
```

这些命令会构建资源、修改项目状态，并可能发布到目标；不能当作日常只读检查。外部目标必须用 `--confirm-external-publish <id>` 显式确认。

`fyasset_test.py` 的退出码：

| 退出码 | 含义 |
|---|---|
| Unity 进程退出码 | 构建/E2E 正常结束（0 成功，1 失败） |
| `2` | 参数或环境无效（`build.config` 缺少 `UnityPath`、Unity 路径不存在） |
| `3` | 前置条件不满足（Editor 正在占用项目、等待超时） |
| `130` | 收到 Ctrl+C 中断 |

运行前核对 `CommandLine/build.config` 中的 `UnityPath`、目标配置、已有数据和 Editor 占用情况。

## 模式

| 模式 | 主要行为 |
|---|---|
| Full | 准备测试状态后构建 Full，并验证交付/目标 |
| Hotfix | 使用或准备同作用域的成功 Full 基准（缺失则先 seed 一次 Full），修改 fixture 后构建 Hotfix |
| Chain | Full、fixture 变更、Hotfix 连续链 |
| E2E | 在构建测试基础上生成并运行 Player；前向更新可复用同一 Player 与隔离持久化目录 |
| Standalone | AB 离线输出交付到 `StreamingAssets/Standalone`，不要求在线发布目标 |

精确序列以 `BuildTestEngine` / `E2ETestEngine` 的当前实现为准。

## 重置与恢复

`fyasset_reset.py` 是破坏性维护入口，不建议在每次测试前无条件执行：

```text
python CommandLine/fyasset_reset.py {aa|ab|all} [--dry-run] [--keep-testruns] [--reports] [--clear-publish]
```

当前清理对象：

| 目标 | 说明 |
|---|---|
| `BuildData/PublishCache/{AA\|AB}` | 本地发布缓存；删除不影响已发布包 |
| `BuildData/Reports/{AA\|AB}` | 仅在 `--reports` 时清理 |
| `HotfixOutput/Packages` | 构建交付包目录（每个包一个 `Build_*` 子目录）；删后不影响已发布包 |
| `HotfixOutput/Hotfix` | 已废弃的累计 Hotfix 目录残留（若存在则删除） |
| `BuildData/Summaries` | 正式构建摘要与索引；删除后项目版本回到 `1.0.0`，历史包目录不被删除 |
| `HotfixOutput/build.log`、`HotfixOutput/TestRuns` | 日志与测试证据（`--keep-testruns` 保留） |
| `Assets/StreamingAssets` 导出物 | `BuildIndex.json`、AA/AB Manifest、catalog、`bundles/`、`Standalone/` 及对应 `.meta` |
| `Assets/Build/Bootstrap/BuildIndex.json` | 若存在则删除 |
| AA Hotfix Group undo log | 重置为空 `Entries` |
| 永久测试 fixture | 恢复为 Full 标记内容 |
| `HotfixPublish/{Local,Cloudflare}` | 仅在 `--clear-publish` 时清理（保留 `_headers`） |

它不会触碰 git 历史、不部署或清空 Cloudflare 公有站点、不删除已知构建/测试归属之外的源资产。`--dry-run` 只打印将执行的操作。

测试引擎会尝试恢复项目与目标，但恢复也可能失败。需要检查 `result.json`、日志、目标身份、临时配置以及残留进程；不要以退出码为零替代人工核对恢复状态。

## 必须单独验收的行为

1. Unity Domain Reload、窗口切换、窄窗口与长路径布局。
2. Collection 的 Project Scan / Curate / Save / Cancel 与未保存提示。
3. 真正的 AA/AB Full/Hotfix/Standalone 产物：完整 Manifest、Hotfix 包（AB 为相对基准 Full 的变化内容）与 BuildIndex。
4. Player 加载：SerializedObject、Scene（Additive/Single）、RawFile、批量加载、Handle token 与 Shutdown 门禁。
5. 下载失败、激活失败、版本异常、索引写入、运行中 Check/Prepare/Apply 与恢复失败。
6. Android StreamingAssets 与独立导出工程，不能由桌面 stub 测试推断。

`BuildTestAcceptance` 中部分 AB Address 检查使用字符串与文件名启发式，不证明运行时可解析；这属于已有验证缺口。历史结果与待验收项保留在 requirements，不在本指南复制为当前通过状态。
