# 字段语义参考表

> **关联代码** | `Assets/FYAsset/Scripts/Shared/` · `Assets/FYAsset/Scripts/AA/` · `Assets/FYAsset/Scripts/AB/`

本文只记录容易混淆、会影响跨模块行为的语义。完整字段和序列化顺序以源码为准。

---

## 高危混淆项

| 对比 | 结论 |
|------|------|
| Asset 加载依赖 / Content 依赖 | 前者是构建期分析的 Asset 级依赖（`BundleDependencyGraph`），只用于规划；后者是运行时事实 `ManifestContentEntry.DependencyIndices`，来自 Unity `AssetBundleManifest` |
| Labels / BundleKey | Labels 属于资产，用于运行时查询；BundleKey 是构建期内容分桶键，不出现在运行时 Manifest |
| Address / SourcePath | Address 是公共查询键（大小写不敏感且唯一）；SourcePath 是传给 Unity 的工程路径，只用于构建与提取 |
| EntryId / AssetGUID | 值都来自 Unity GUID；EntryId 是运行时命名，AssetGUID 是构建期命名，必须一对一 |
| PrimaryType / ContentType | PrimaryType 是单个资产的主类型名；`AssetContentType` 决定构建与加载路线（SerializedObject / Scene / RawFile），两者不能互相代替 |
| `AssetContentType` / `AssetDependencyOrigin` | 前者决定“怎么产出与加载”，后者决定“为什么进入构建集合”（显式/隐式）；Origin 不进入运行时 Manifest |
| `ContentEntries` / Hotfix 交付集合 | `ContentEntries` 是完整运行时内容表；Hotfix 交付集合（`ABDeliveryContents`）是本次包内实际携带的文件，两者不可互换 |
| 构建摘要 / 内容复用事实 / 发布缓存 | 三者复用 `FileDigest` 但存储与生命周期分离：`BuildData/Summaries/{AA\|AB}/{BuildId}.json`（正式摘要与 `SummaryContentFact` 复用事实）、历史 `Build_*` 包字节（复用来源）、`BuildData/PublishCache`（发布提示） |
| PackageIndex / BuildIndex | 远端 PackageIndex 指向目标包；本地 PackageIndex 指向最近成功激活包；BuildIndex 描述安装包内置身份与 `RuntimeMode` |
| `BuildType` / `RuntimeMode` | 前者是构建模式（Full/Hotfix/Standalone）；后者是构建导出的运行模式（Online/Standalone），运行时只读 `BuildIndex.RuntimeMode` |
| Version / Build | 发布身份是 `Major.Minor.Patch[-Channel]`；Build 是独立计数，不参与比较，也不进入发布版本字符串 |

## 配置归属

| 配置 | 负责内容 |
|------|----------|
| `FYAssetSettings` | 项目名、构建输出根与包目录名、BuildIndex 路径、Push Targets |
| `FYAssetBackendSettings`（Compat） | 宿主后端选择（AA / AB）；由 GameLauncher 序列化引用读取，只用于本仓库测试/宿主胶水 |
| `FYAssetAASettings` | AA HotfixUrl、下载参数、AA Pipeline 路径、Manifest 输出格式、热更包大小阈值 |
| `FYAssetABSettings` | AB PlayMode、HotfixUrl、下载参数、AB Pipeline 路径、Manifest 输出格式、热更包大小阈值、AssetCollection 配置路径、`DependencyFilterExtensions` |
| `AssetCollectionSetting` | Address 样式、Groups/Collectors、Address 与 Labels 覆盖、忽略、排除、RawFile 白名单、共享策略 |
| `BuildPipelineConfig` | `BundleCompression`、自定义 Task 的 `TaskName + Slot` |
| 构建事实（`BuildSummaryIndex` / `BuildVersionPlanner`） | 产品版本源：`BuildData/Summaries/index.json` 的 `ProjectVersion` 保存全局成功版本与当日计数，不按 AA/AB 拆分 |

后端选择只由 Compat 的 `FYAssetBackendSettings` 决定，且**不创建、不选择、不切换后端实现**；正式 AA/AB 构建入口与运行时入口各自固定使用所属后端。

## 资源身份链

| 阶段 | 关键结构 | 身份与查询语义 |
|------|----------|----------------|
| Collector | `AssetOverride` / `AssetExclusion` | GUID 是权威键；Address 可自动生成或被覆盖锁定；排除按 GUID 生效 |
| 构建中间态 | `CollectedAssetInfo` | 汇总路径、GUID、Address、PrimaryType、Labels、GroupName、ContentName、`AssetContentType`、`AssetDependencyOrigin`、`IsPublic` |
| Manifest | `ManifestAssetEntry` | `EntryId` 唯一；`Address` 只对 `IsPublic` 条目有意义；`ContentIndex` 指向 `ContentEntries` |
| Manifest | `ManifestContentEntry` | `FileName` + `FileHash` + `FileCRC` + `FileSize` + `ContentType` + `DependencyIndices` |
| 运行时 | `RuntimeAssetEntry` | 复制查询元数据与 Labels；`ContentIndex` 留在 Manifest |
| Handle | `AssetHandle<T>` / `SceneHandle` | 独立 token + Generation 校验；错误由 `RuntimeMessage` 传播 |

公共 Address 冲突不是可容忍状态：单包内大小写不敏感唯一，构建期与运行期都严格阻断。

## ABManifest

```csharp
[BinarySerializable(Magic = 0x41424D46, SchemaVersion = 6)]
public class ABManifest
{
    public VersionNumber PackageVersion;
    public List<ManifestAssetEntry> AssetEntries;
    public List<ManifestContentEntry> ContentEntries;
}
```

| 结构 | 字段 |
|---|---|
| `ManifestAssetEntry` | `EntryId`、`Address`、`PrimaryType`、`Labels`、`SourcePath`、`IsPublic`、`ContentType`、`ContentIndex` |
| `ManifestContentEntry` | `FileName`、`FileHash`、`FileCRC`、`FileSize`、`ContentType`、`DependencyIndices` |

- 一个 `ManifestContentEntry` 可被多个 `ManifestAssetEntry` 通过 `ContentIndex` 指向，形成一对多映射。
- `Initialize()` 建立 Address（只含 `IsPublic`）、EntryId、FileName 索引；索引只做查询加速，不做数据校验——坏数据由构建期 `VerifyABContent` 阻断。
- 运行时 `_addressIndex` 使用 `StringComparer.OrdinalIgnoreCase`；`FileName` 索引同名只保留首个。
- 已删除字段：Manifest 的 `PackageName` / `BuildTimestamp` / 自引用 `FileHash` / `DeliveryBundles`；Asset 条目的 `Group` / `AutoAddress` / `BundleIndex` / `PayloadKind`；Content 条目的 `BundleType` / `Tags` / `Encrypted`。`ManifestBundleEntry` 改名为 `ManifestContentEntry`，`BundleEntries` 改名 `ContentEntries`。

## 构建摘要、复用事实与差异

```csharp
public readonly struct FileDigest { string Name; string Hash; uint CRC; long Size; }

public sealed class FileDiff { List<FileDigest> Added, Modified, Unchanged; List<string> Removed; }

public sealed class CompleteBuildSummary
{
    string BuildId; string ArtifactRelativePath; string BaseFullSummaryId;
    string BackendId; BuildType BuildType; RuntimeMode RuntimeMode;
    VersionNumber Version; string Platform; DateTime StartedAt; TimeSpan Duration; bool Success;
    List<FileDigest> Files; List<SummaryContentFact> Contents;
    List<BuildMessage> Messages; BuildStatistics Statistics;
}

public sealed class SummaryContentFact
{
    string ContentIdentity; string InputFingerprint;
    string FileName; string FileHash; uint FileCRC; long FileSize;
    List<string> DependencyFileNames;
}

public sealed class PublishCache
{
    string BackendId; string TargetId; List<FileDigest> Files;
    string LastPackageName; string PublishedAtUtc;
}
```

| 语义 | 说明 |
|---|---|
| `FileDigest.Hash` | 内容 MD5，小写十六进制；`Matches` 要求 Name/Hash/CRC/Size 四字段全等 |
| `FileDiff` 名称比较 | `Ordinal`（大小写敏感），因为包内文件名由构建侧统一产生 |
| `CompleteBuildSummary` | 构建结果面板唯一数据源；不含绝对路径，落盘用可序列化 DTO（DateTime/TimeSpan/readonly struct 不在 Unity 序列化范围内） |
| `SummaryContentFact.DependencyFileNames` | 被复用内容不会出现在本轮 `AssetBundleManifest` 中，必须靠复用事实回放依赖下标；为 null 表示缺事实，不可复用（空集合是叶子内容的合法事实） |
| `PublishCache` | 只做辅助与双重检测，不能替代服务器事实；缺失或损坏不改变发布结果 |

## 包体与版本指针

| 结构 | 关键语义 |
|------|----------|
| `VersionNumber` | struct 值类型；比较顺序 Major → Minor → Patch → Channel，Build 不参与；复制后修改不会更新原值 |
| `PackageIndex` | `LatestPackage` / `LatestVersion` / `BackendMode`；远端指向目标包，本地记录上次成功完成初始化的包 |
| `BuildIndexData` | `BuildGUID` / `BuildTime` / `IsDebug` / `Platform` / `BackendMode` / `Version` / `RuntimeMode`；`Version.Major` 是兼容边界，`RuntimeMode` 是联网与否的唯一事实 |
| `AAManifest` | AA 内容校验信息与 Addressables 查询索引；catalog 仍负责实际定位 |
| `ABManifest` | 完整 Asset/Content 映射与内容级依赖下标 |
| `AASourceScan.json` | AA 源快照（GUID → Asset+meta 摘要），写在包根并随包交付，供下一次 Hotfix 计算源差异 |

AA 与 AB 的 PackageIndex 与发布目录必须隔离。`HotfixOutput/Packages` 保存构建交付包（每个包一个 `Build_*` 目录）；不再存在固定累计 Hotfix 目录，AB Hotfix 包只携带相对基准 Full 的变化内容（AA 的相对 Full 裁剪属延期矩阵）。

## 枚举边界

| 枚举 | 解决的问题 | 关键值 |
|------|------------|--------|
| `AssetContentType` | 资产如何构建与加载 | `SerializedObject` / `Scene` / `RawFile` |
| `AssetDependencyOrigin` | 资产如何进入构建集合 | `Explicit` / `Implicit`（只服务构建诊断） |
| `BundlePackingMode` | Group 如何形成内容 | `PackTogether` / `PackSeparately` / `PackTogetherByLabel` |
| `ECollectPathType` | Collector 绑定目录还是文件 | `Folder` / `File` |
| `AssetAddressStyle` | 自动 Address 生成样式 | `ShortName`（枚举默认值 0） / `LongAssetPathWithoutExtension`（本项目配置值） / `NameType` |
| `BundleCompression` | Bundle 压缩模式 | `LZ4` / `LZMA` / `Uncompressed` |
| `BuildType` | 构建模式 | `Full` / `Hotfix` / `Standalone` |
| `RuntimeMode` | 运行时是否联网 | `Online` / `Standalone` |
| `ManifestOutputFormat` | 清单落盘格式 | `JsonOnly` / `JsonAndBinary` / `BinaryOnly` |
| `HotfixContentState` | 本次启动使用哪个包 | `BuiltIn` / `Local` / `RemoteTarget` / `Blocked` |
| `HotfixStateAction` | 状态机高层动作 | `KeepCurrent` / `RepairPointer` / `RepairPackage` / `PrepareTarget` / `RejectRemote` / `Block` |
| `HotfixPhase` | 运行中热更阶段 | `Check` / `Prepare` / `Apply` |

“为什么被收集”（Origin）、“以什么格式输出”（ContentType）和“能否被业务查询”（IsPublic）是三件正交的事，不能混成一个枚举。

## BuildContext 使用原则

BuildContext 是 Task 间数据总线，不是长期状态：

1. `IBuildRunEnvironment.PrepareContext` 写入请求、模式与输出路径。
2. 采集、依赖、内容构建、manifest、验证、导出按固定主干顺序传递。
3. 必需输入使用 `Require<T>`，可选输入使用 `Get<T>`。
4. 中性 Key 放 `BuildContextKeys`，后端私有 Key 放 `AABuildContextKeys` / `ABBuildContextKeys`；不要在 Task 内发明同义字符串。
5. 交付清单与历史差异不进入 Context。

## 命名规则

- 对外字段使用 PascalCase；同语义跨结构保持同名。
- 资产级分类统一叫 Labels；不再有 Bundle 级 Tags 字段。
- 文件内容哈希统一叫 FileHash；摘要结构统一叫 `FileDigest`。
- 公共 Address 承诺大小写不敏感且唯一；EntryId 承诺全局唯一。
- 本地文件路径、AssetDatabase 路径和 URL 使用各自的路径工具，不混用拼接规则。
