# 命令行构建指南

> **关联代码** \| `Assets/FYAsset/Scripts/Shared/Build/` · `Assets/FYAsset/Scripts/AB/Build/Collector/Editor/` · `CommandLine/`

## 概述

项目支持在 Unity Editor 外部通过命令行执行资源构建，适用于 CI/CD 集成和批量出包场景。正式构建入口为 `BuildCommandLine.Build`，当前支持 `full`、`hotfix`、`standalone` 三种 `-buildType`。

命令行正式构建仍走 Compat 的 `BuildProjectManager` 入口：`full` / `hotfix` 由 `Assets/Build/FYAssetBackendSettings.asset` 路由；`standalone` 当前固定走 AB 管线。`BuildCommandLine.Build` 不通过命令行参数覆盖 AA/AB 后端。Repository CLI 的 `-backend` 只用于仓库通道选择。

## 构建流程全景

AB 从 Collection 采集、依赖分析与 Bundle 构建进入 Manifest 和交付；AA 从 Addressables source/Group 与 BuildPlayerContent 进入输出整理。两者由具体 Backend 调用共享线性 Runner，不共用 Collector 起点。

每次构建产出：
- **Bundle 文件**：实际的 AssetBundle 资源包
- **当前后端 Manifest**：AA 生成 AAManifest；AB 生成 ABManifest，其中 `BundleEntries` 是完整运行时表，`DeliveryBundles` 是 AB Hotfix 构建/发布交付列表
- **PackageIndex**：远端最新包体指针，记录最新包名、版本和后端模式；访问位置由发布根 + `BuildPackagesFolderName` + 包名推导
- **BuildIndexData**：Full Build 本地启动索引，记录版本、包 GUID 和后端模式

## 快速开始

### 1. 配置 Unity 路径

编辑 `CommandLine/build.config`：

```ini
UnityPath="~\2022.3.6f1c1\Editor\Unity.exe"
```

### 2. 执行构建

推荐在 CI 中直接调用 `BuildCommandLine.Build`。`CommandLine/build.bat` 仍可作为本地包装脚本使用；正式入口识别 `full` / `hotfix` / `standalone`：

```
Unity.exe -batchmode -quit -projectPath <path> \
  -executeMethod BuildCommandLine.Build -buildType standalone
```

日志路径由 Unity 的 `-logFile` 或包装脚本指定，不由 BuildCommandLine 固定为某个目录。

## 构建模式

| 模式 | 版本变化 | 产出 | 适用场景 |
|------|---------|------|---------|
| Hotfix | Patch+1 | 热更清单 + 当前后端实际交付内容；AB 为 `DeliveryBundles`，AA 为 Addressables Hotfix 输出 | 修 bug、更新单个资源 |
| Full Package | Major+1 | 全量 Bundle + 完整清单 | 大版本发布、基线刷新 |
| Standalone | Major+1 | 先生成 attempt，再交付 ABManifest 与 Bundle 到 `StreamingAssets/Standalone/`；写 BuildIndex，不写 PackageIndex/baseline | AB 离线包，平台支持需独立验证 |

构建成功记录交付基线；外部 Push 是独立显式操作，不是历史 Repository commit。

## CI/CD 集成

在 CI 环境中直接调用 Unity 命令行：

```bash
Unity.exe -batchmode -quit \
    -projectPath "E:/unity/project/XLuaHotfix" \
    -executeMethod BuildCommandLine.Build \
    -buildType hotfix \
    -logFile "HotfixOutput/build.log"
```

支持的 `-buildType` 参数：`hotfix`、`full`、`standalone`。

## 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 构建成功 |
| 1 | 构建失败（详见日志） |

## 前置条件与注意事项

- **同项目 Editor 占用**：不要同时用另一 Unity 实例打开同一项目；包装脚本与直接 Unity 命令的检查能力不同。
- **配置就绪**：AB 需要 Collection，AA 需要 Addressables；两侧均需要对应 Pipeline 与版本配置。
- **命令行后端选择来自 Compat 配置**：切换 AA/AB 请修改 `Assets/Build/FYAssetBackendSettings.asset` 的 `Backend`，不要通过构建命令行覆盖
- **AB Hotfix 需要 Full baseline**：执行 AB Hotfix 前必须已有同 Channel/Backend/Major 的 AB LatestFull baseline，否则构建会在 diff/delivery 阶段失败
- **构建完成后检查日志**：`HotfixOutput/build.log` 包含完整构建记录和错误详情
- **批量构建**：可通过脚本循环调用不同 `-buildType` 实现多模式连续构建
- **自动化验收**：Build/E2E 测试 CLI 见 [自动化测试管线](./自动化测试管线.md)（`fyasset-test` / `fyasset_reset` / batch）
