## 设计目标

自研AssetBundle资源管理系统，替换Addressables的资源加载机制。
笔者之前借Addressable资源管理系统，自己设计了Hotfix流程和导出包管理。现自研AssetBundle资源管理系统，替换Addressables的资源加载机制。过程中通过接口后端分离，实现重构时的逐步替换。

## Legacy（基于Addressable的旧设计） vs AB（自研） 对比

> TODO: 当前对比不够细致，还需继续完善

| 维度       | Legacy (Addressables)                  | AB (自研)                                 |
| -------- | -------------------------------------- | --------------------------------------- |
| **索引源**  | AddressableLabelsConfig SO             | ABManifest JSON（后续引入二进制序列化）             |
| **加载后端** | AddressablesBackend → Addressables API | ABPackageBackend → AssetBundle API      |
| **依赖解析** | Addressables 内部自动                      | ABBundleLoader 递归解析 Bundle 级依赖          |
| **引用计数** | 单层（AsyncOperationHandle）               | 双层（Bundle 级 + Asset 级）                  |
| **资源标识** | Address 唯一，只有Labels标签                  | Address 可重复，EntryId 唯一，引入Type，保留Labels  |
| **错误处理** | 异常 + null                              | AssetLoadError 结构化错误码                   |
| **句柄模型** | 直接返回 T                                 | AssetHandle\<T> struct + HandleRegistry |

## 核心数据结构

以下为核心数据结构示例，整个资源管理系统围绕这些数据结构进行设计（与实际代码有一定出入）

- **ManifestAssetEntry（资产索引项）（构建期）**

```csharp
public class ManifestAssetEntry
{
    // 运行时必须字段（与 RuntimeAssetEntry 保持一致）
    public string EntryId; // 唯一资源ID（GUID）
    public string Address; // 可寻址逻辑名（允许重复，默认由文件名去扩展自动生成）
    public string PrimaryType; // 资源类型名（如 "Texture2D"、"Mesh" 等）
    public List<string> Labels = new();// 分类标签，用于查询分类策略

    public int BundleIndex; // 所属资源包索引（运行时使用）

    // 编辑器字段
    public string SourcePath;// 资源文件路径（构建时使用）
    public string Group;     // 资源分组（构建时使用）

    public RuntimeAssetEntry ToRuntimeEntry() {} // 转换为 RuntimeAssetEntry（不含 BundleIndex，由 ABAssetIndex 另行维护映射）
}
```

- **AssetHandle（资产句柄）（运行时）**

```csharp
// 泛型资源句柄 — Load 操作的主要返回类型（值类型，零 GC）
public struct AssetHandle<T> where T : UnityEngine.Object
{
    internal int HandleId;// HandleRegistry 中的槽位索引
    internal int Generation;// 创建时的handle版本快照， 用于判断有效性
    private T _cachedAsset;// 缓存的资源引用（热路径优化：读 .Asset 时直接返回，避免查 Registry）
    private AssetLoadError _inlineError;// 失败句柄的内联错误（HandleId=-1 时使用，不通过 Registry 存储）

    // internal 构造函数（成功/失败）

    // 公开属性
    public T Asset;// 已加载的资源。Handle 无效（释放/过期/失败）时返回 null
    public bool IsValid;// 是否有效（未释放/未过期/加载成功）
    public AssetLoadError Error;// 结构化错误信息（成功：内联错误，失败：Registry 错误或 null）

    // Retain/Release 均通过 HandleRegistry 调度
    // 共享所有权：显式调用 Retain() 增加引用计数
    public AssetHandle<T> Retain() { HandleRegistry.Retain(_handleId, _generation); return this; }
    public void Release() { HandleRegistry.Release(_handleId, _generation); }
}
```

## 统一的错误处理约定

内外 API 采用不同的返回类型约定：
内部用tuple传递，外部用统一的AssetHandle包装

| 层级                                     | 返回类型                                                | 理由                               |
| -------------------------------------- | --------------------------------------------------- | -------------------------------- |
| ABBundleLoader → ABPackageBackend      | `(AssetBundle, AssetLoadError)` ValueTuple          | 内部无需句柄，直接传递错误                    |
| ABPackageBackend → AssetPackageManager | `(T, string bundleName, AssetLoadError)` ValueTuple | 需要 bundleName 注册到 HandleRegistry |
| AssetPackageManager → 调用方              | `AssetHandle<T>` struct                             | 统一外部接口，值语义零 GC                   |
| AssetPackageManager → 调用方 (Legacy)     | `AssetHandle<T>` struct                             | Legacy 路径也走 HandleRegistry，保持一致  |

**AssetLoadError 错误码**：

| Code                  | 含义                       |
| --------------------- | ------------------------ |
| NotFound              | 条目不存在                    |
| AmbiguousMatch        | Address 重复且无法消歧          |
| TypeMismatch          | PrimaryType 与请求类型不兼容     |
| BundleNotFound        | Bundle 文件缺失              |
| BundleLoadFailed      | Bundle 加载失败（I/O、CRC 等）   |
| DependencyFailed      | 依赖 Bundle 加载失败           |
| AssetExtractionFailed | AssetBundle.LoadAsset 失败 |
| LoadFailed            | 通用加载失败                   |

### 关键设计决策（TODO： 后续改为项目特点与YooAsset和Addressable等对比）

| # | 决策                             | 理由                                      |
| - | ------------------------------ | --------------------------------------- |
| 1 | Address 允许重复，EntryId 唯一        | 同名资源多版本共存，GUID 保证内部一致性                  |
| 2 | Group 仅构建时使用，不参与运行时查询          | 运行时按 Address/Type/Labels 查询，Group 是打包概念 |
| 3 | 双层引用计数（Bundle + Asset）         | Bundle 级控制卸载粒度，Asset 级精确追踪使用            |
| 4 | AssetHandle\<T> 为 struct       | 值语义零 GC，Generation 防悬空                  |
| 5 | USE\_AB\_INDEX 一个开关控制两个维度      | 不存在"AB 索引 + Addressables 后端"组合          |
| 6 | Bundle 级依赖（无 Asset 级依赖）        | 数据模型简单，运行时递归解析开销可接受                     |
| 7 | AssetBundle.Unload(true) 引用归零时 | 连同 Asset 一起卸载，避免残留                      |
| 8 | 内部 ValueTuple / 外部 AssetHandle | 内部高效传递，外部统一安全接口                         |

## 运行期

### 双层引用计数

AB 路径采用 Bundle + Asset 双层引用计数，配合 Handle 层对外暴露，实现精确的卸载粒度控制。

#### 三层架构

| 层级           | 管理者              | 数据结构                                               | 职责                                         |
| ------------ | ---------------- | -------------------------------------------------- | ------------------------------------------ |
| **Handle 层** | HandleRegistry   | `Slot[]` 数组                                        | 管理外部持有的 `AssetHandle<T>` 引用计数，归零时触发释放回调    |
| **Asset 层**  | ABPackageBackend | `_assetCache: Dict<address, AssetCacheEntry>`      | 管理从 Bundle 中提取的 Asset 引用计数，归零时联动 Bundle 卸载 |
| **Bundle 层** | ABBundleLoader   | `_bundleCache: Dict<bundleName, BundleCacheEntry>` | 管理 AssetBundle 文件引用计数，归零时执行 `Unload(true)` |

#### 加载流程

**第一步：用户调用加载接口**

```
用户调用 AssetPackageManager.LoadByAddress<T>(address)
    ↓
AssetResolver.ResolveByAddress 解析得到 ManifestAssetEntry
    ↓
调用 ABPackageBackend.LoadAssetTupleAsync<T>(address, entryId)
```

**第二步：Asset 层处理**

```
ABPackageBackend 检查 _assetCache 是否已缓存该 Asset：
    ├─ 命中：AssetCacheEntry.RefCount++，直接返回缓存的 Asset
    └─ 未命中：
         ├─ 通过 ABManifest 查询 Asset 所属的 Bundle
         ├─ 调用 ABBundleLoader.LoadBundleAsync(bundleName)
         ├─ 从 Bundle 中提取 Asset：bundle.LoadAssetAsync<T>(sourcePath)
         └─ 加入 _assetCache，RefCount = 1
```

**第三步：Bundle 层处理**

```
ABBundleLoader 检查 _bundleCache 是否已缓存该 Bundle：
    ├─ 命中：BundleCacheEntry.RefCount++，直接返回缓存的 AssetBundle
    └─ 未命中：
         ├─ 解析 Bundle 物理路径（热更目录优先，StreamingAssets 回退）
         ├─ 加载 AssetBundle：AssetBundle.LoadFromFileAsync(path)
         ├─ 递归加载依赖 Bundle（每个依赖 Bundle 的 RefCount 同样 +1）
         └─ 加入 _bundleCache，RefCount = 1
```

**第四步：Handle 层分配**

```
AssetPackageManager 调用 HandleRegistry.Alloc(entryId, bundleName, null, releaseCallback)
    ↓
分配 Slot，RefCount = 1，Generation = 当前值
    ↓
返回 AssetHandle<T> 给用户（包含 handleId、generation、cachedAsset）
```

#### 卸载流程

**第一步：用户调用 Release**

```
用户调用 handle.Release()
    ↓
HandleRegistry.Release(handleId, generation)
    ↓
校验 Generation 是否匹配（防止过期 Handle 或拷贝体误释放）
    ├─ 不匹配：输出 Warning，返回 false（安全空操作）
    └─ 匹配：Slot.RefCount--
```

**第二步：Handle 引用归零处理**

```
Slot.RefCount 归零时：
    ├─ 执行 ReleaseCallback（即 abBackend.UnloadByEntryId(entryId)）
    ├─ 清理 Slot 状态，Generation++
    └─ 归还 FreeList
```

**第三步：Asset 层卸载**

```
ABPackageBackend.UnloadByEntryId(entryId)
    ↓
通过 _entryIdToAddress 反查 address
    ↓
从 _assetCache 获取 AssetCacheEntry，RefCount--
    ↓
RefCount 归零时：
    ├─ 移除 _assetCache 条目
    ├─ 清理 _entryIdToAddress 反向映射
    └─ 调用 _bundleLoader.UnloadBundle(bundleName)
```

**第四步：Bundle 层卸载**

```
ABBundleLoader.UnloadBundle(bundleName)
    ↓
从 _bundleCache 获取 BundleCacheEntry，RefCount--
    ↓
RefCount 归零时：
    ├─ 执行 AssetBundle.Unload(true)（连同内部所有 Asset 一起卸载）
    ├─ 移除 _bundleCache 条目
    └─ 递归调用 UnloadBundle 处理依赖 Bundle
```

#### 关键规则

**引用计数语义**

- Bundle RefCount = 该 Bundle 下所有已加载 Asset 的引用数之和
- Asset RefCount = 该 Asset 对应的 Handle 引用数之和（通过 ReleaseCallback 联动）
- Handle RefCount = 外部显式持有的引用数（Load 时 = 1，Retain 时 +1）

**卸载触发条件**

- Asset RefCount 归零 → 移除 Asset 缓存 → 递减 Bundle RefCount
- Bundle RefCount 归零 → `AssetBundle.Unload(true)` → 递归卸载依赖 Bundle
- 依赖 Bundle 的 RefCount 在加载时同步递增，卸载时同步递减

**安全保护机制**

- Handle 使用 Generation 校验：过期 Handle 或拷贝体的 Release 会被拦截为空操作
- 拷贝体不自动 Retain：如需共享所有权，必须显式调用 `handle.Retain()`
- 加载失败返回无效 Handle（HandleId = -1），Release 为空操作

**依赖 Bundle 处理**

- 加载主 Bundle 时，ABBundleLoader 通过 ABManifest 查询直接依赖，递归加载
- 使用 HashSet 防环：已访问的 Bundle 不会重复加载
- 加载失败时回滚：已加载的依赖 Bundle 会被立即卸载

#### 运行期资源加载调用链

**AB 路径完整调用链**：

1. **用户层**：`AssetPackageManager.LoadByAddress<T>(address)`
2. **解析层**：`AssetResolver.ResolveByAddress<T>(_index, address)` → 得到 `ManifestAssetEntry`
3. **后端调用**：`ABPackageBackend.LoadAssetTupleAsync<T>(address, entryId)`
4. **Bundle 加载**：`ABBundleLoader.LoadBundleAsync(bundleName)`
   - 递归加载依赖 Bundle
   - 加载 AssetBundle 文件
5. **Asset 提取**：`bundle.LoadAssetAsync<T>(sourcePath)`
6. **句柄分配**：`HandleRegistry.Alloc(entryId, bundleName, null, releaseCallback)`
7. **返回句柄**：`new AssetHandle<T>(handleId, generation, asset)`
