# FYAsset 资源管理总览

> **关联代码** | [FYAsset/Scripts](../../Assets/FYAsset/Scripts/)

FYAsset 包含 Addressables（AA）与自研 AssetBundle（AB）两条具体实现。真实项目只能直接使用其中一个后端，不混合、不自动切换；两者只共用无后端字段的基础协议与流程语义。本文提供职责导航；详细调用链与全部 C# 文件职责见 [HTML 建模文档](./fyasset-modeling.html)。

## 四段管线

```text
构建与完整包导出
→ 无状态差异比较
→ 本地交付与发布
→ 运行时热更
```

| 阶段 | 事实来源 | 结果 | 专题 |
|---|---|---|---|
| 构建与完整包导出 | 后端固定主干 + 配置里的自定义 Task | 完整构建结果（`CompleteBuildSummary`）、模式输出与 BuildIndex | [Build Pipeline](./build-pipeline-构建管线.md) |
| 无状态差异比较 | 两份 `FileDigest` 集合 | `FileDiff`（Added / Modified / Unchanged / Removed） | [无状态差异](./diff-无状态差异.md) |
| 本地交付与发布 | 服务器 `PackageIndex` + 其指向的 Manifest | 不可变新包目录 + 最后写入的 `PackageIndex` | [本地交付与发布](./publish-本地交付与发布.md) |
| 运行时热更 | `BuildIndex`、本地/远端 `PackageIndex`、`HotfixStateDecider` | 一次启动只读取一个包根的完整包 | [Hotfix](./hotfix-热更新系统.md) |

构建与热更是核心；差异与发布是小型辅助流程。框架不引入 Git：不提交、不回滚、不管理外部版本历史，使用方可依据构建信息自行接入 Git、CI 或制品库。

## 所有权

| 目录 | 负责 | 不负责 |
|---|---|---|
| `AA/` | Addressables 构建、catalog、AAManifest、AA 资源加载与热更后端 | AB 采集、Bundle 加载 |
| `AB/` | Collection、依赖分析、ABManifest、内容构建与缓存、Bundle/Scene/RawFile 加载 | Addressables Group 修改 |
| `Shared/` | 线性 Task 编排、版本、无状态文件摘要与差异、发布事务、热更状态机与隔离目录 | 宿主选择 AA/AB；不引用 Catalog、AAManifest、ABManifest、Bundle 构建结果、Collector 等后端字段 |
| `Compat/` | 宿主后端选择、门面、Lua 索引构建接入、Cloudflare 发布接入 | 替代 AA/AB 的具体实现 |
| `Tests/` | 构建测试、E2E、测试服务和验证入口 | 正式业务运行入口 |

`Assets/Tools/Scripts/Serialization` 是通用序列化工具。FYAsset 的类型注册与生成代码归 `Compat/Serialization`，不是工具内置类型。目录边界不等于已经拆分成独立程序集或可单独导出安装的包。

## 核心流程

| 流程 | 输入与结果 | 边界 |
|---|---|---|
| AB Collection | Project Scan 得到只读预览，确认后进入 Curate 候选配置；Save 验证并持久化 | 显式 Collector 收集到的资源都是公共资源；隐式依赖由构建阶段内部化 |
| AB 构建 | CollectABAssets → AnalyzeABDependencies → BuildABContent → GenerateABManifest → VerifyABContent → ExportABOutput | 主干固定 6 段，每段之间允许 `0..N` 自定义 Task |
| AA 构建 | PrepareAAInput → BuildAAContent → GenerateAAManifest → VerifyAAContent → ExportAAOutput | 主干固定 5 段；Group 修改必须由 AA 入口 `try/finally` 恢复 |
| 差异比较 | 两份文件摘要集合，按名称配对比较 Hash/CRC/Size | 不读 Git、PackageIndex、缓存或任何历史状态 |
| 本地交付与发布 | 构建产物提升到正式出口；发布在新隔离目录复用服务器已有 Hash 内容并最后写 `PackageIndex` | 发布不删除旧包；旧包清理是独立维护入口 |
| 热更 | 读取并校验 BuildIndex → 校验内置包 → 决定保持/修复/前向更新/阻断 → 准备、校验并激活 | 激活后只读一个包根，绝不逐文件回退 StreamingAssets |
| 运行时 | AA 通过 Addressables，AB 通过公共索引、Backend、BundleLoader 与 SceneLoader | 普通资源只能通过 Handle 持有；Handle 与 SceneHandle 共用活跃计数门禁 |

构建输出目录职责不同：默认 `HotfixOutput/Packages` 保存构建交付包（每个包一个 `Build_*` 独立目录，Standalone 交付到 `StreamingAssets/Standalone`），`HotfixPublish` 保存发布镜像或部署暂存数据；构建摘要与索引住在 `BuildData/Summaries`。没有固定累计 Hotfix 目录：AB Hotfix 包只携带相对基准 Full 的变化内容（AA 的相对 Full 裁剪属延期矩阵）。运行时使用单独配置的 URL，不依赖这些本地目录名称。

## AA 与 AB

| 维度 | AA | AB |
|---|---|---|
| 定位 | Addressables catalog + AAManifest | ABManifest（Asset/Content 一对多映射） |
| 内容构建 | Addressables `BuildPlayerContent` | Unity `BuildAssetBundles` + 构建缓存复用 |
| 加载 | `AAPackageManager` / Addressables | `ABPackageManager` / `ABPackageBackend` / `ABBundleLoader` / `ABSceneLoader` |
| 生命周期 | Addressables Handle tickets | Handle token 槽位表 + 每个 EntryId 的活跃 token 计数 |
| 构建入口 | `AABuildProjectManager` | `ABBuildProjectManager` |
| 配置 | `FYAssetAASettings` | `FYAssetABSettings`，含 PlayMode 与 AssetCollection |

`BackendMode` 只作为身份校验和诊断字段，不创建、不选择、不切换后端；后端身份不一致一律 Error 严格阻断。Compat 的 `FYAssetBackendSettings` 只服务本仓库测试/宿主胶水，不是正式兼容入口。

## 四组容易混淆的概念

| 对照 | 结论 |
|---|---|
| Asset 加载 / Asset 依赖 | Asset 加载是运行时的公共 Address → 内容 → Handle 链路；Asset 依赖是构建期分析出的“这个资产还需要哪些资产”，只用于规划打包 |
| Asset 依赖 / Bundle(Content) 依赖 | 前者是构建期 `BundleDependencyGraph` 计划图；后者是运行时 `ManifestContentEntry.DependencyIndices`，事实来自 Unity 构建后的 `AssetBundleManifest` |
| 构建期 Hotfix / 运行时 Hotfix | 构建期 Hotfix 是打包模式（相对基准 Full 的变化交付）；运行时 Hotfix 是独立的第四阶段状态机，两者不共享数据模型 |
| 正式 Standalone / 在线临时内置包退化 | Standalone 由 `BuildIndex.RuntimeMode=Standalone` 决定且不联网；在线退化到内置包只是本次启动的 Warning 兜底，不改变 RuntimeMode，下次启动照常 Check |

## 事实边界

本文按源码描述，不以历史测试通过推导当前所有流程正确。交付补偿和发布事务都会遇到补偿本身失败的情况，不提供跨文件、跨网络的不可失败保证。真实 Unity 构建、Player、Android StreamingAssets 与远端部署需要分别验证；具体未决验收保留在 requirements。
