# 命令行构建指南

> **关联代码** | `Assets/FYAsset/Scripts/Shared/Build/` · `Assets/FYAsset/Scripts/AB/Build/Collector/Editor/` · `Assets/FYAsset/Scripts/Compat/Editor/BuildCommandLine.cs` · `CommandLine/`

## 概述

项目支持在 Unity Editor 外部通过命令行执行资源构建，适用于 CI/CD 集成和批量出包场景。正式构建入口为 `BuildCommandLine.Build`，当前支持 `full`、`hotfix`、`standalone` 三种 `-buildType`。

命令行正式构建走 Compat 的 `BuildProjectManager` 门面：`full` / `hotfix` 按 `Assets/Build/FYAssetBackendSettings.asset` 里的 `Backend` 路由到 AA 或 AB；`standalone` 当前固定走 AB 管线。

---

## 构建流程全景

```text
AB：CollectABAssets → AnalyzeABDependencies → BuildABContent → GenerateABManifest → VerifyABContent → ExportABOutput
AA：PrepareAAInput → BuildAAContent → GenerateAAManifest → VerifyAAContent → ExportAAOutput
```

两者都由各自 PipelineBackbone 固定主干，配置只声明自定义 Task 的插入槽位，再由共享 Runner 顺序执行；Runner 不写 PackageIndex、不做发布。每次构建的产物：

| 产物 | 说明 |
|---|---|
| **内容文件** | AB 为 `bundles/` 下的 AssetBundle 与 RawFile；AA 为 Addressables 输出的 bundles 与 `catalog.json` |
| **当前后端 Manifest** | AA 生成 `AAManifest.json/.bin`；AB 生成 `ABManifest.json/.bin`，其中 `AssetEntries` 是资源表，`ContentEntries` 是完整内容表（含依赖下标） |
| **BuildIndexData** | Full / Standalone 写包内与 StreamingAssets 的 `BuildIndex.json`，含版本、BuildGUID、后端与 `RuntimeMode` |
| **构建摘要** | `BuildData/Summaries/{AA\|AB}/{BuildId}.json`（不可变）与可重建的 `BuildData/Summaries/index.json`；属于构建事实，不进入包目录 |
| **Hotfix 交付内容** | AB：完整目标 `ABManifest` + 相对最近成功 Full 的新增/修改内容；AA：本次 Addressables 构建的产出内容 + `AAManifest` / `catalog.json` / `AASourceScan.json`（AA 的相对 Full 内容裁剪属延期矩阵）。基准由 `BuildData/Summaries/index.json` 的 `LatestFullSummaryId` 定位 |
| **PackageIndex** | **构建不写**；由发布事务在内容就位并校验通过后最后生成上传 |

## 快速开始

### 1. 配置 Unity 路径

编辑 `CommandLine/build.config`：

```ini
UnityPath="~\2022.3.6f1c1\Editor\Unity.exe"
```

### 2. 执行构建

推荐在 CI 中直接调用 `BuildCommandLine.Build`。`CommandLine/build.bat` 仍可作为本地包装脚本使用：

```text
Unity.exe -batchmode -quit -projectPath <path> \
  -executeMethod BuildCommandLine.Build -buildType standalone
```

日志路径由 Unity 的 `-logFile` 或包装脚本指定，不由 `BuildCommandLine` 固定为某个目录。

## 构建模式

| 模式 | 版本变化 | 产出 | 适用场景 |
|------|---------|------|---------|
| `full` | Major+1 | 完整内置包（`RuntimeMode=Online`）+ 完整 Manifest + 全部内容，交付到 `Packages/Build_*` 独立目录 | 大版本发布、建立 Full 基准 |
| `hotfix` | Patch+1 | AB：完整目标 Manifest + 相对最近成功 Full 的变化内容；AA：本次 Addressables 构建的产出内容；都交付到独立 `Build_*` 目录，不覆盖安装包 BuildIndex | 修 bug、更新单个资源 |
| `standalone` | Major+1 | 完整离线包（`RuntimeMode=Standalone`），交付到 `StreamingAssets/Standalone/`；不写 PackageIndex | AB 离线包，平台支持需独立验证 |

交付与发布是两件事：构建成功只完成本地交付事务（正式包目录、StreamingAssets 启动数据、正式构建摘要与 Summary Index）；外部 Push 是独立显式操作。

## CI/CD 集成

```bash
Unity.exe -batchmode -quit \
    -projectPath "E:/unity/project/XLuaHotfix" \
    -executeMethod BuildCommandLine.Build \
    -buildType hotfix \
    -logFile "HotfixOutput/build.log"
```

支持的 `-buildType` 参数：`hotfix`、`full`、`standalone`。`BuildCommandLine` 不识别其他构建模式，未知取值直接 `Exit(1)`。

## 退出码

| 退出码 | 含义 |
|--------|------|
| 0 | 构建成功（`BuildCommandLine` 显式 `EditorApplication.Exit(0)`） |
| 1 | 构建失败或未知 buildType（详见日志） |

## 前置条件与注意事项

- **同项目 Editor 占用**：不要同时用另一 Unity 实例打开同一项目；包装脚本与直接 Unity 命令的检查能力不同。
- **配置就绪**：AB 需要 Collection 配置（`AssetCollectionSetting`）；AA 需要 Addressables；两侧都需要对应 Pipeline 配置。
- **命令行后端选择来自 Compat 配置**：切换 AA/AB 请修改 `Assets/Build/FYAssetBackendSettings.asset` 的 `Backend`，不要通过构建命令行覆盖。
- **Hotfix 需要基准 Full**：构建事实里必须有同后端、同平台、同通道的成功 Full（`HotfixBaselineResolver` 按 Summary Index 作用域定位），否则 Export / PrepareAAInput 阶段以明确原因中止。
- **失败不污染正式输出**：attempt 布局下 Runner 失败只回收中间产物，正式输出与构建事实保持运行前状态。
- **构建完成后检查日志**：日志包含完整构建记录和错误详情；构建摘要落在 `BuildData/Summaries/{AA\|AB}/{BuildId}.json`，含文件清单与内容复用事实。
- **批量构建**：可通过脚本循环调用不同 `-buildType` 实现多模式连续构建。
- **自动化验收**：Build/E2E 测试 CLI 与隔离场景见 [自动化测试管线](./自动化测试管线.md)（`fyasset_test.py` / `fyasset_reset.py` / `dotnet run --project tests/scenario/*`）。
- **本地发布镜像服务**：`CommandLine/hotfix_server.py` 提供只读静态文件服务（含 `__fyasset_health` 健康检查），默认根目录为 `HotfixPublish/Local/{AA|AB}`；它只服务发布镜像，不参与构建。AB Test 面板的 Start/Stop/Status 复用它。
